## 1. 三分钟理解: Skill vs Playbook

| 你想做的事 | 用什么 | 入口 |
|---|---|---|
| 「现在跑一下信源健康扫描」| **Skill** (单原子) | `/skill-store` 卡片 → 「跑一次」|
| 「每周一 9 点自动跑 Top5 事件 + 邮件」| **Playbook** (多步编排) | `playbooks/*.yml` + `scheduler` |
| 「KL 完成时检查质量」| **Skill** (内置 quality-patrol, KL T1-T5 自动触发) | 后台自动 |
| 「GitHub push 触发某个 skill」| **Webhook** | `POST /api/trigger/webhook/{source}` |

**Skill** = 单原子任务 (一个 prompt + 一个输出, 内置 / 用户自建)
**Playbook** = 多步骤 YAML, 可调用多个 skill / api / condition

## 2. 启用 Skill 商店 (feature gate)

默认 `skill_registry=false` 关闭 (fail-closed)。开启:

```toml
# backend/config/feature_gates.toml
[extensions]
skill_registry = true   # /skill-store 路由 + 5 端点
trigger_gate = true      # trigger-gate + webhook 入口
user_skills = true       # 用户自建 Skill (/skill-store/new)
playbook_engine = true   # Playbook YAML + Cron
```

重启 backend 后, 浏览器访问 `/skill-store` 即可看到 20 个内置 skill。

## 4. 使用 Skill

### 4.1 手动跑一次

1. 浏览器 `/skill-store`
2. 找到目标 skill 卡片 (可按类别 / 类型 / 启停过滤)
3. 点「跑一次」 → 卡片内联提示「已加入执行队列 · ticket tg-xxx」

ticket_id 形如 `tg-a1b2c3d4e5f6`, 可在 dashboard `/dashboard` 看到时间线状态。

### 4.2 启停 Skill

1. 卡片右上角 toggle 二次确认 → 状态实时刷新
2. 启停写到 `settings.kv` (key=`skill.<id>.enabled`); 默认值来自
   `default_enabled`, 关掉 `user_skills` gate 后 KV 不会立即生效

### 4.3 查看详情 / 历史

- 详情页: `/skill-store/<skill_id>` — schema + 输入输出 + prompt (C/D 类)
- 历史回放: `/skill-store/<skill_id>?focus=history` — 最近 20 条运行
- 👍👎 反馈: 历史条目末尾按钮, 一次提交即锁定 (供 recall 学习)

### 4.4 用户自建 Skill

1. `/skill-store/new` → 4 步向导
   - 步骤 1: 基本信息 (id / name / category / skill_type)
   - 步骤 2: Schema (字段定义) + C/D 类 prompt 模板
   - 步骤 3: Target (调用的 service.module.Class.method)
   - 步骤 4: 复核 + 保存 (默认 enabled=0, 启用走 PATCH)
2. 「试运行校验」调 `/api/skill-builder/validate` 返回错误明细
3. 单用户上限 50 个 skill (soft delete 计数不计入)

## 5. 使用 Playbook

### 5.1 YAML 格式 (kind=Playbook)

```yaml
kind: Playbook
metadata:
  name: daily-source-health
  desc: '每日信源健康巡检'
  inputs:
    top_n:
      type: int
      default: 10
trigger:
  cron: "0 9 * * *"
  timezone: Asia/Shanghai
steps:
  - id: scan
    kind: skill
    skill: source-health-scan
    params:
      top_n: "{{ inputs.top_n }}"
    output: scan_result
  - id: ticket_if_dead
    kind: api
    action: POST /api/codegarden/tickets
    if_expr: scan_result.stats.dead > 0
    body:
      title: "信源失活: {{ steps.scan_result.top_dead[0].name }}"
      severity: high
  - id: outputs
    kind: api
    action: POST /api/dashboard/snapshot
    body:
      source: playbook:daily-source-health
      data: "{{ steps.scan_result }}"
```

### 5.2 Step 类型

| kind | 字段 | 说明 |
|---|---|---|
| `skill` | `skill`, `params` | 调 builtin / user skill (校验已注册, R8) |
| `api` | `action`, `body`, `if_expr` | HTTP 客户端调用 (`METHOD /path`) |
| `condition` | `expr` | 简单布尔表达式, 求值为 False 时跳过本步 |

### 5.3 上限与守卫

- 单 playbook ≤ 50 步, 总执行 ≤ 1 小时 (R6)
- 禁用 `script` 类型 (R7: RCE 边界)
- 危险命令黑名单 (`sudo` / `rm -rf` / `curl|sh` 等 11 类) 拦截
- 引用未注册 skill → validate 报错 (R8)

### 5.4 Cron 调度

```bash
# 注册 / 调度 (通过 API)
curl -X POST http://localhost:8000/api/scheduler/playbooks \
  -d '{"playbook_name": "daily-source-health", "cron_spec": "0 9 * * *"}'

# 或在 playbooks/*.yml 顶部写 trigger.cron, 启动时自动注册 (scheduler.py)
```

## 6. 触发源 (v0.8 Phase D D1 新增)

### 6.1 Webhook

```bash
# 无 secret (dev)
curl -X POST http://localhost:8000/api/trigger/webhook/secnews \
  -H "Content-Type: application/json" \
  -d '{"event": "push", "ref": "main"}'

# 有 secret (prod, R7 fail-closed)
SECRET=$(cat ~/.config/hotspot/webhook-secret)
SIG=$(echo -n "/api/trigger/webhook/secnews|$(body)" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')
curl -X POST http://localhost:8000/api/trigger/webhook/secnews \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Signature: $SIG" \
  -d "$body"
```

合法 `source` 名单: `github` / `stripe` / `secnews` / `custom` / `cve_feed` / `cti`。
非白名单 → 422 (R12 fail loud)。

### 6.2 KL 事件

KL T1-T5 任一阶段完成时, 内部自动调 `submit_kl_event(stage, item_id)`,
目标 skill 默认 `quality-patrol` (A 类, builtin)。

### 6.3 Collector 事件

collector 失败 / 超时时, 内部自动调 `submit_collector_event(name, status)`,
目标 skill 默认 `source-health-scan` (A 类, builtin)。
- `failed` → NORMAL 优先级
- `timeout` → REALTIME 优先级
- `success` → 不触发 (健康常态不浪费 60/min 限流配额)

## 7. 看板 (Dashboard)

`/dashboard` 一屏看全:

- **健康指标**: 活跃信源 / 已启用技能 / 待处理票据 / 限流状态 (ok/caution/saturated)
- **技能状态矩阵**: 全部 skill 的 id / name / type / category / enabled
- **触发器时间线**: 最近触发的 ticket (source + target + status + 相对时间)

真实「触发器时间线」数据面要等 `/api/trigger/tickets` 落地 (v0.9);
当前 v0.8 用 mock 数据兜底。
