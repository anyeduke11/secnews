## 1. 产品与交互原则

Hotspot 是安全从业者工作台。用户的主对象是资料、关注对象、事项、判断、行动、成果、经验；dsh/pi 是内部组件，主要在运行详情或系统诊断中显示。

首屏回答“今天需要我判断什么、补什么、批准什么、验收什么”。六个 Skill 以对应业务动作出现，也在能力中心统一管理；不要求用户记忆 SK 编号或选择一个空白聊天会话。

对话只作为 Case 内的“补充说明/继续研判”，携带明确证据和对象版本，输出必须进入已有 Judgment/Action/Artifact。它不能绕过批准或直接改写事实。

## 2. 信息架构与 URL

| 路径 | 页面职责 | 关键规则 |
|---|---|---|
| `/` | 默认进入今日工作 | 在新工作台验收后切换；此前保留旧入口可访问 |
| `/workbench` | 今日待办与关键变化 | 不展示运行时仪表盘作为主内容 |
| `/intel` | 精选、待核实、历史资料 | 视图/来源/主题/时间写 URL query |
| `/intel/:signalId` | 事件证据与变化 | 查看多源原文、加入/创建 Case |
| `/cases` | 按工作阶段组织事项 | 列表优先，阶段筛选，支持保存视图 |
| `/cases/:caseId/:section?` | 事项工作区 | section 为 overview/evidence/judgments/actions/artifacts/review |
| `/knowledge` | 经验与历史资料目录 | published 与待校验历史资料明确分层 |
| `/knowledge/:knowledgeId` | 经验详情、条件与采用 | 预留旧静态子路径，不被动态 ID 吞掉 |
| `/subjects` | 岗位/关注对象与资产版本 | 导入预览、错误行、别名、快照 |
| `/sources` | 信源与采集状态 | 尝试/成功/新内容分开，显示重试原因 |
| `/skill-store` | 能力中心 | 复用现有路径，前台名称为“能力” |
| `/runs/:runId` | 真实运行与成果 | 步骤、模式、版本、日志、取消和恢复 |
| `/settings` | 配置、诊断与维护 | dsh/pi、模型、数据环境、备份位于此处 |

新增路径为目标契约，开始开发前检查命名冲突。`/knowledge/import|process|compile|imported|deep-read/...` 先保留现有行为，再按对象身份做兼容跳转；禁止全部重定向到知识首页。`/judge`、`/action`、`/garden`、`/secnews` 等旧入口按功能清单决定兼容，不删除尚未承接的功能。

一个应用壳只渲染一次主导航、ToastProvider 和页头。去掉 V1Prototype 的内层四主入口 tabs；页面状态由 router 决定，组件内 useState 不再作为第二套导航真相。刷新/后退必须回到相同对象和筛选，浏览器标题包含当前工作对象。

## 3. 应用壳与视觉规范

桌面采用可折叠主导航和可伸缩工作区，主导航只列四个主入口，辅助能力折叠。宽屏把空间留给证据与比较，不做巨幅标题、欢迎 Hero 或空白装饰。

| 项目 | 约束 |
|---|---|
| 品牌 | 页头明确显示 Hotspot，旁边是环境/服务状态；品牌不是只藏在 tiny nav |
| 字体 | 中文正文用现有系统无衬线栈；正文 14px、辅助 12px、页标题 22px、面板标题 16px；数字 tabular-nums |
| 字距 | 0；不用负字距和随 viewport 连续缩放字体 |
| 色彩 | 保留浅/深主题及语义色；中性底，操作用克制强调色；黄=需处理，红=失败/风险，绿=已确认；不能只靠颜色表达状态 |
| 圆角/容器 | 控件及必要重复项 4..8px；业务 section 不做浮动大卡片；不在卡片中再嵌卡片 |
| 密度 | 桌面表格行 44..48px、工具栏 40..44px；列宽稳定、长标题换行或明确展开，禁止 hover 改变布局尺寸 |
| 图标 | 复用已安装的统一库；当前若无库，统一引入 lucide-react，一次锁版本；替换主导航 emoji，不手绘重复 SVG 图标 |
| 图像/原文 | 使用真实资料截图、文档预览和实际成果，不用装饰图片冒充证据；截图标来源和时间 |
| 控件 | Tab 切视图、checkbox 选择、toggle 控制独立开关、menu 选项、数字 input 控预算；命令按钮用图标+明确动词 |
| 可访问性 | 可见焦点、键盘顺序、语义表头、label 与错误关联；普通文字对比至少 4.5:1，状态不只颜色 |
| 动效 | 120..200ms 必要过渡，尊重 reduced-motion；无滚动劫持、炫光或自动跳页 |

复用现有 CSS 语义 token，先解决缺失变量/对比/重复壳，再调整具体色值。不要另写一套仅 v1 生效的硬编码背景。具体色板通过真实页面截图检查后定稿，不把设计技能中的装饰建议视为工作台需求。

响应式：1440/1280px 支持侧栏+双栏证据阅读；1024px 折叠辅助栏；768px 单主栏，证据在抽屉；390px 显示紧凑顶栏、筛选菜单与顺序化任务步骤。移动端触控目标至少 44px，底部操作条不得遮挡正文/软键盘；不强行把完整桌面表格压进手机。

## 4. 今日工作

布局为页头、单行状态摘要、待办队列、关键情报变化。统计来自与列表相同的服务查询条件及 as_of，点击数字直接筛选对应任务。

| 区域 | 显示字段 | 动作 |
|---|---|---|
| 待判断 | Case 问题、关注对象、最新证据、优先级、期限 | 进入证据研判 |
| 待补充 | 缺失字段/证据、阻塞原因、谁可补充 | 补充资料或修改范围 |
| 待批准 | Action 目的、scope、计划版本、工具/权限、预算 | 审阅计划 |
| 待验收 | 成果名称、验证状态、完成条件、运行时间 | 打开产物并验收 |
| 待复查 | 经验、到期/反证原因、受影响事项 | 对比新证据 |
| 关键变化 | 新确认/版本扩大/补丁/撤回、相关对象 | 看变化并加入事项 |

首屏不放所有源健康曲线和 dsh/pi 进程按钮；关键源故障确实影响工作时展示可操作告警。所有待办为空时显示真实“暂无待处理事项”，仍可创建事项/查看资料；API 失败时不显示该空状态。

## 5. 情报、资料与信源

情报默认按价值展示事件，不按爬到的条数堆新闻。一个事件展示标题、影响对象、证据等级、来源数、新变化、时间、当前确认状态；点击打开多源证据，不把转载数等同于独立确认。

三种视图明确分开：精选、待核实、历史资料。待核实条目带“尚缺什么证据”，历史资料保留来源与原生命周期，尚未重评时不显示已验证标识。操作包括收藏、暂缓、加入 Case、创建 Case；忽略偏好不能改写证据置信度。

资料详情可读取实际正文/原始快照，显示来源、抓取时间、原文发布时间、parser/rule/revision、hash 和引用范围；hash 默认在详情折叠，不占主列表。

信源中心使用表格，字段包含启用、类型、频率、最近尝试、最近有效获取、最近新增、失败类别、重试时间与解析版本。暂停抓取和停用个性化精选分开；恢复来源后有计划的追抓预算。429、正常 304 和解析异常不能使用同一个红色失败文案。

关注对象支持 CSV/JSON 预览、字段映射、逐行错误、导入确认与版本差异；用户不填敏感资产也可研究，但系统只能给通用判断，不能冒充已确认组织影响。

## 6. Case 工作区：用户真正完成工作的地方

顶部稳定显示问题、目标、范围、对象快照、优先级、期限和当前阻塞。页内 section tabs 切换证据/判断/行动/成果/复盘，始终保留 Case 身份。

### 6.1 创建和证据

从情报创建时自动携带选中的 evidence IDs，不自动接受推断；用户确认研究/影响研判/行动跟进模板及完成条件。追加资料保留版本，不覆盖旧判断引用。没有对象信息显示待补充，不凭“无 Artifact”猜测缺资产。

### 6.2 判断审阅

桌面左侧证据原文，右侧结构化判断；移动端采用引用 drawer。每条关键 claim 显示支持/反证/未知及适用条件，引用点击定位具体 revision 和 quote。

动作：生成研判、补充说明、要求补证、人工修订、接受判断、标记争议。生成中可取消，失败保留输入与上下文。修订生成独立作者/版本；发布前展示引用验证结果，关键引用失效不能通过。

### 6.3 行动批准和执行

展示目的、scope、计划步骤、工具版本、权限、预算、预期成果、完成标准和有效期。批准绑定具体 plan_hash；计划变更后旧批准失效，必须展示 diff 重新确认。

开始运行后显示实际模式及步骤状态；模型未配置、pi 未构建或工具缺依赖时显示 blocked 和原因。取消是取消请求，等 runtime 回执后再显示 cancelled；部分成果可保留。涉及非幂等副作用的重试说明哪些步骤会重跑，必要时重新批准。

### 6.4 成果验收

必须能预览/下载真实成果，显示预期与实际、工具回执、存储/hash 校验、业务完成条件。分清“运行结束”“校验通过”“验收通过”。

接受/退回操作包含 expected_revision，冲突返回当前版本并保留评语。缺文件时直接显示“成果不可读取”，禁止绿色通过。退回后展示修改要求和后续新 attempt，不用重新上传同一 hash 绕过历史退回。

### 6.5 关闭和复盘

后端决定是否满足该 Case 模板的完成条件；有历史 Action 关联不是关闭阻断理由。用户变更目标后关闭必须留原因。已关闭 Case 新增关键反证进入待复查，不改写历史验收。

复盘提炼来自已验收成果，区分事实、方法、例外和失败教训；可生成经验草稿，但发布需补齐前提、证据和复查日期。

## 7. 知识与六个能力

经验详情包括来源链、适用条件、已知例外、验证方式、版本、复查时间、采用历史。知识图谱是辅助浏览，不能替代原文或用边数表示质量。

“在当前事项采用”打开条件比较：旧对象版本/范围与当前对象对照；用户选择采用、调整后采用或不采用，并留理由。真正采用后才创建 adoption receipt。失效或撤回经验不得作为当前高置信依据，历史使用记录保持可读。

| 能力 | 自然入口 | 最小输入 | 可验收输出 |
|---|---|---|---|
| 每日优先情报 | 今日工作/情报 | 岗位、关注对象、时间窗、阅读预算 | 有来源与排序原因的事件清单 |
| 漏洞影响研判 | Case 判断 | Case、对象快照、CVE、证据包 | 可审阅 Judgment 草稿和未知项 |
| 排查材料生成 | 已接受判断的行动区 | 判断版本、范围、预期材料 | Plan、真实运行和可读成果 |
| 行动后经验提炼 | 已验收成果的复盘区 | Action/Artifact/验收引用 | 带前提与例外的经验草稿 |
| 经验复用 | 新 Case 的证据/判断区 | 当前问题、对象版本、候选知识 | 条件比较、采用决定及回执 |
| 经验复查 | 今日待复查/知识 | 到期项或反证 | 待复查任务、关联 Case 影响 |

能力中心保留用途、输入、工具/权限、版本、依赖和历史。三个控制独立表达：“允许新手动任务”“自动触发”“取消当前运行”；关闭自动触发不等于撤销历史成果。运行入口依赖后端返回的可用能力，不靠 UI 隐藏实现权限。

## 8. 所有页面必须覆盖的状态

| 状态 | UI 行为 | 不允许 |
|---|---|---|
| loading | 保持布局的骨架，已有内容可保留 | 每次刷新清空整个页面 |
| empty | 确认请求成功后显示空状态和业务动作 | 失败后返回“暂无数据” |
| unavailable | 明确服务不可达、重试与诊断入口 | 伪造 0 个待办/100%健康 |
| stale | 保留最后成功数据，显示更新时间和陈旧提示 | 旧数据无时间地冒充最新 |
| partial | 成功区域保留，失败区域单独重试 | 任一子请求失败就全页空白 |
| migrating/incomplete | 显示迁移水位、尚缺正文/引用与可读历史 | 将缺内容知识标 published |
| disabled/blocked | 显示被停用或缺哪项依赖 | 按钮可点但后台 noop |
| conflict | 409 展示当前版本差异，保留输入 | 自动覆盖新版本或丢掉评语 |
| failed/timed_out | 原因、部分成果、受控重试/取消 | 自动重试有副作用动作 |
| accepted/published | 展示实际成果/证据链接与确认记录 | 根据点击或乐观本地状态宣告成功 |

健康横幅表达“后端不可达”“历史数据可读，执行暂停”等实际状态。技术详情放可展开诊断，主操作页不堆 schema/table/SK 编号或原型说明。

## 9. 前端实现顺序与测试

先修 API URL 和错误模型，再拆分 V1Prototype，随后接入 mutation 和事件。建议页面组件：WorkbenchPage、IntelPage、CasesPage、CaseDetailPage、KnowledgePage；先查现有命名空间避免平行目录，公共组件包括 AsyncState、EvidenceViewer、RunTimeline、ArtifactReview、ApplicabilityDiff。

共享 query key 包含 environment_id、对象 ID、筛选和分页；主页面查询来源唯一，优先复用现有可用 hook。若现有缓存不足再单独引入查询库，不把状态库迁移作为服务恢复前提。

测试必须覆盖：四 URL 直接进入对应页面；知识静态旧路径不冲突；Case 刷新/返回保留状态；请求参数含多个过滤项仍正确；API 断开不显示空数据；完整 mutation 链；SSE 同 tab 刷新；409 恢复；停用能力；390/768/1280/1440 截图与键盘焦点。

每个截图使用真实或明确隔离的业务夹具，不能凭视觉完整宣布真实上游接通。上线后移除生产 mock fallback/原型横幅；测试资产留在测试目录，与真实数据源隔离。
