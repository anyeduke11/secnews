## 2. 用户画像与核心场景

单用户（owner）双角色：**审批者**（审批执行计划，默认拒绝）与**兜底执行者**（AI 执行体不可用/不适用时人工完成并在账本登记）。核心场景：

1. **人工回执闭环**：作为研究者，我批准一条 Action 并启动 Run，AI 执行体不在场时我人工完成工作（如本地复现验证），在四段指挥台把 Run 标记 succeeded/failed 并登记产物——Case 因此可以真实关闭。
2. **审批执行计划**：作为审批者，我审阅 dsh 生成的 ExecutionPlan（允许的命令/可写路径/网络/超时），默认全拒，逐条放行；审批快照被冻结留审计。
3. **边界内自动执行**：作为研究者，我放行的 plan 由 pi 在 enforce 约束内执行，事件流实时可见，产物自动登记 body_hash。
4. **越界可见**：作为运维者，pi 尝试 plan 外命令时被拦截并告警，我能在失败面板看到原因码。
5. **经验回流**：作为研究者，Case 关闭时复盘经验自动起草为提案，我批准后发布为 Knowledge，下一个同类 Case 自动召回。

## 4. 需求详述（R-1 ~ R-6）

> 每项含：现状（file:line）/ 需求 / 技术约束 / 验收（二值）/ 回滚。安全底线八条（外部执行授权 / 范围限制 / 凭据保护 / 出站控制 / 审计留痕 / 失败真实性 / 资源上限 / 审批快照版本追溯）为**不可关闭的系统底线**，全需求适用。

### 4.1 R-1 Run 人工回执通道（direct 执行体 + Action 收口）

| 项 | 内容 |
|---|---|
| 现状 | RunService 无 claim/start/finish 方法（run_service.py:96-200）；action 无收口端点（action_api.py:196-231 仅 approve/start/cancel）；`finish_run` 无生产调用方（run_ledger_api.py:12） |
| 需求 | ① RunService 增 `claim/start/finish/cancel` 四方法（CAS 状态迁移，7 态机对齐：queued→claimed→running→终态；finish 必填 outcome ∈ {done, failed, cancelled, timeout, needs_human} + error 原因码）；② HTTP 端点 `POST /api/v1/runs/{id}/claim|start|finish|cancel`（人 = 执行者，protocol='direct'）；③ `POST /api/v1/actions/{id}/finish`（running→succeeded/failed 收口，校验关联 run 终态）；④ 四段指挥台 Run 段接线操作按钮（既有 ActionCommandConsole 下挂）；⑤ finish 时发 `v1_run` outbox 事件 |
| 技术约束 | CAS 迁移复用 `update_status` + revision 语义（防双击重复终态）；人登记 = 人担保（L1 审批天然满足，登记写 audit_log）；**禁止**绕过守卫直接 succeeded——须有 artifact 或显式 error |
| 验收 | ① 一条真实 action：start→run→人工 finish(succeeded, outcome=done)→artifact 登记(verify+accept)→**case 关闭成功**（首个 closed case）；② 重复 finish 返回 409（CAS）；③ run 生命周期在 outbox 可查 |
| 回滚 | 单 commit revert（端点为增量，无 schema 变更） |

| 项 | 内容 |
|---|---|
| 现状 | 无 ExecutionPlan 任何代码对应物；plan_json 列装的是账本审批快照（run_ledger_service.py:305-306），语义不同 |
| 需求 | ① **schema v1**（Pydantic）：`commands[]`（argv 级逐条）/ `writable_paths[]` / `readable_paths[]` / `network[]`（默认全禁）/ `timeout_sec`（单命令 + 总时长）/ `output_artifact`（类型 + 验收要点）；② 生成：dsh 不可达时**人工手写 plan 兜底**（结构化表单，P10 裁决③）；dsh 可达时经 ai_hub 正常场景调用生成建议 plan（**不碰 `_try_order`/`_resolve_provider` 红线**）；③ 审批 API `POST /api/v1/runs/{id}/plan/approve|reject`（**默认拒绝**；审批时冻结 plan 快照 + 版本号写入 run 行）；④ 四段指挥台 plan 审批区块（差异要点展示）；⑤ 试点只读类 Action 模板（P10 裁决④：如「汇总某 CVE 本地产物生成 brief 草稿」，零写入风险） |

## 6. 安全模型（四层防线 × 八条底线映射）

| 层 | 机制 | v0.8.9 状态 |
|---|---|---|
| L1 计划层 | plan 默认拒绝；人审批 = 放行；审批快照 immutable | R-2 交付 |
| L2 进程层 | workspace 锁定（agent_bridge 已有）+ argv 白名单 ∩ plan 子集 + 网络默认全禁 | R-3 交付 |
| L3 系统层 | ulimit + sandbox-exec per-plan profile | R-4 交付（best-effort，Docker 留后续） |
| L4 审计层 | 全量 stdin/stdout/exit 落 agent_runs + plan 逐条比对 + 越界告警 | R-3/R-4 交付 |

八条不可关闭底线逐条落位：外部执行授权 = L1 审批；范围限制 = L2；凭据保护 = 执行环境无 llm_secrets；出站控制 = network[] 默认全禁；审计留痕 = L4 + audit_log；失败真实性 = 7 态机显式 outcome；资源上限 = timeout/budget + ulimit；审批快照版本追溯 = boundary_hash + revision。

## 10. 风险与熔断

| 风险 | 概率/影响 | 缓解 |
|---|---|---|
| pi 执行体能力不达预期（单轮补全限制下多步任务体验差） | 中/中 | 人工回执通道并行存在（R-1 永为兜底）；试点从只读类起步 |
| 边界 enforce 被绕过 | 低/**高** | L4 逐条比对 + 越界即 fail + 告警；L3 兜底；红线演练为发布门 |
| migration 加列漂移 | 中/低 | X-6 只加不改；`generate_meta --check` 门 |
| 范围蔓延（把"通车"做成"加功能"） | 中/中 | §3.1 明确不做清单；任何新功能需求另立版本 |
| 观测窗数据不足 30 天判定 | 中/低 | 判定窗口 t0 = R-1 交付日；不足则如实标「观测中」不宣称达标 |

**熔断红线**：越界命令在 L4/L3 任一层未被拦截（立即停 R-3 → 回滚 executor 开关）；主干链路出现基线外 pytest 失败 2h 未定位；plan 审批快照被发现可被未审批修改。
