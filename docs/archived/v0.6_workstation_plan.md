# v0.6 Hotspot 工作台重构方案

> **产品身份**：集成 DeepSeek Harness 的安全从业者 AI 工作台
> **取代**：v0.5 SPEC 的 M3/M4 部分（M1/M2/M3.5/M5 已完成工作保留）
> **PRD 参考**：`~/Documents/dsh-SecNews/SECNEWS-v5-PRD.md` M1-M7 模块映射到 hotspot 代码

---

## §0 第一性原理

1. **工作台 ≠ 聚合器**：采集是管道，不是产品。用户来工作台是「做事」。
2. **安全从业者 = 判断密集型**：帮用户从碎片信息中形成判断，不是推送资讯。
3. **集成 dsh ≠ 依赖 dsh**：hotspot 独立可运行，dsh 增强推理。dsh 故障 → LLM 直连兜底。
4. **wiki-first 存储**：知识域以 llm-wiki-2.0 md 为唯一真相源，SQLite 做投影索引。
5. **行动域 SQLite-first**：favorites/todos/reviews/kl_queue 以 DB 为真相，单向投影回 wiki。

## §4 Phase 3：KL 管线落地

**目标**：实现 SECNEWS-v5-PRD 的 F1 沉淀主流程——wiki-first 摄入 + KL 状态机 + 管线观测。

### P3.1 kl_queue 表 + 状态机

- 新建迁移：`backend/repository/migrations/066_kl_queue.sql`
  ```sql
  CREATE TABLE IF NOT EXISTS kl_queue (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id TEXT NOT NULL,          -- wiki item hash/id
    stage TEXT NOT NULL DEFAULT 'raw',  -- raw|refine|link|structure|published|failed
    stage_entered_at TEXT NOT NULL DEFAULT (datetime('now')),
    attempts INTEGER DEFAULT 0,
    error TEXT,
    model_tier TEXT,                -- flash|standard|heavy
    tokens_used INTEGER DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
  );
  CREATE INDEX idx_kl_stage ON kl_queue(stage, stage_entered_at);
  CREATE INDEX idx_kl_item ON kl_queue(item_id);
  ```
- 新建：`backend/services/kl/pipeline.py` (~200行)
  - `KLPipeline` 类: 状态机驱动
  - `enqueue(item_id)` → 创建 kl_queue 行 (stage=raw)
  - `advance(queue_id)` → 执行当前阶段 → 推进到下一阶段
  - 阶段实现: `_do_refine()` / `_do_link()` / `_do_structure()` / `_do_publish()`
  - 每个阶段: try → 成功 advance / except → stage=failed + error 记录
- 新建：`backend/services/kl/__init__.py`

### P3.2 摄入管道 wiki-first 改造

**当前**：`collection_service.py` → `HotspotRepository.upsert_many()` → SQLite

- 修改：`backend/services/collection_service.py`
  - `collect_and_process()` 流程改为：
    1. 采集 + quality gates（不变）
    2. 通过 quality 的 item → `knowledge.wiki_io.write_item()` 即写 md
    3. 同时 `HotspotRepository.upsert_many()` 写 SQLite 投影
  - 关键：md 写入失败 → item 不入 SQLite（wiki-first 强约束）
