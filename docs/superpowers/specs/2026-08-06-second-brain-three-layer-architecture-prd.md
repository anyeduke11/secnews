## 1. 战略定位

### 1.1 项目名称

**Second Brain 三层架构** — 在 SecNews 热点聚合平台基础上，将资讯、标讯、知识管理、项目管理统一抽象为三层结构。

### 1.2 核心定位

从"信息聚合工具"升级为"第二大脑"：

| 层 | 核心问题 | 解决什么 |
|----|---------|---------|
| 资料层 | 我有什么 | 信息过载 → 统一采集和存储 |
| 判断层 | 我怎么看 | 噪音干扰 → 筛选、分类、分析、关联 |
| 行动层 | 我下一步做什么 | 信息闲置 → 计划、学习、创作、执行 |

### 1.3 设计原则

- **统一抽象**：资讯、标讯、知识、项目 4 条业务线共用同一三层框架
- **最小破坏**：所有现有功能保留，只重新组织导航和页面归属
- **渐进整合**：先导航层重组，再逐层深化功能

## 3. 导航重构

### 3.1 当前导航（现状）

```
[All] [AI] [安全] [金融] [创业] [标讯] [GitHub]  │  [知识管理] [CodeGarden] [设置]
```

按领域分类的扁平导航，知识管理独立 4 大 Tab。

### 3.2 新导航（目标）

```
[资料层]  [判断层]  [行动层]  │  [设置]
```

三层作为顶层导航，替代原有领域分类导航。

### 3.3 层内导航

每层页面顶部保留领域/业务线筛选器，格式统一为：

```
┌──────────────────────────────────────────────────┐
│ [全部] [AI] [安全] [金融] [创业] [标讯] [GitHub]  │  ← 领域筛选
│ [排序] [时间范围] [搜索]                           │  ← 操作栏
└──────────────────────────────────────────────────┘
```

### 3.4 路由结构

```
/                    → 重定向到 /data (资料层)
/data                → 资料层首页
/data/news           → 资讯流
/data/bid            → 标讯列表
/data/favorites      → 收藏夹
/data/history        → 历史记录
/data/import         → 知识导入 (原 KnowledgeImport)
/data/search         → 搜索

/judge               → 判断层首页
/judge/quality       → 质量门禁 (原 QualityRejectionPage)
/judge/trends        → 趋势分析
/judge/bid-analysis  → 标讯分析 (新增)
/judge/heatmap       → 注意力热力图
/judge/graph         → 知识图谱 (原 KnowledgeProcess)
/judge/compile       → 知识库编译 (原 KnowledgeCompile)
/judge/read          → 阅读模式 (简报/扫描/深度/告警)

/action              → 行动层首页
/action/report       → 报告生成 (原 ReportPage)
/action/outbox       → 整理 (原 OutboxMode)
/action/review       → 复习 (原 ReviewMode)
/action/compound     → 知识复利 (原 KnowledgeCompound)
/action/codegarden   → CodeGarden 项目管理
/action/todos        → 待办 (原 TodosPage)
/action/skills       → 技能 (原 SkillsPage)
/action/bid-alert    → 投标提醒 (新增)

/settings            → 设置 (原 SettingsPage)
/settings/sync       → 同步 (原 SyncPage)
/settings/secrets    → 密钥 (原 SecretsPage)
```

### 3.5 兼容处理

SPA 客户端重定向，不涉及 HTTP 301：

- 旧路由 `/category/:cat` → Navigate 到 `/data?category=:cat`
- 旧路由 `/knowledge/*` → Navigate 到对应新路由（`/knowledge/import` → `/data/import`, `/knowledge/process` → `/judge/graph`, `/knowledge/compile` → `/judge/compile`, `/knowledge/compound` → `/action/compound`）
- 旧路由 `/codegarden/*` → Navigate 到 `/action/codegarden`
- 旧路由 `/` → Navigate 到 `/data`
- 过渡期保留 `KnowledgePage` 壳组件，内部路由到新三层页面

## 7. 业务流与跨层联动

### 7.1 三条业务流

#### 资讯业务流

```
资料层                        判断层                      行动层
30+ 数据源采集    →    13 道质量门禁过滤    →    日报/周报/月报生成
7 领域热点聚合    →    AI 分类 + 趋势分析   →    告警推送
搜索/收藏/归档    →    注意力评分           →    整理输出
                   →    知识图谱关联         →    知识库归档
```

#### 标讯业务流

```
资料层                        判断层                      行动层
政府/企业采购采集  →    地区分布分析         →    投标提醒
标讯列表展示       →    状态分析             →    竞争分析
                   →    业务线 4 线分类      →    投标日历
                   →    时效性过滤           →    统计报表
```

#### 知识业务流

```
资料层                        判断层                      行动层
Cubox 同步         →    知识图谱构建         →    学习路径生成
书签导入           →    LLM 编译             →    掌握度评估
URL 验证           →    SOUL 画像更新        →    创作选题
Obsidian 入口      →    健康度评估           →    内容发布
                   →    联邦搜索             →    CodeGarden 项目
```

### 7.2 跨层导航

每层页面顶部提供"上/下层"快捷跳转：

```
[← 资料层]  [判断层]  [行动层 →]
```

### 7.3 上下文联动

当用户在某一层筛选特定领域时，跨层跳转携带该筛选上下文：

```
资料层 筛选 "AI" → 跳转到判断层 → 判断层默认展示 AI 领域分析
判断层 分析标讯 → 跳转到行动层 → 行动层展示标讯相关的投标提醒
```
