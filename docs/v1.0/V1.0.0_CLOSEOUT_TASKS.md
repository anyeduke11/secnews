## 1. 每批统一执行规则

1. 读根/就近 AGENTS、DEV_LOG、CHECK_LOG 和本任务引用文件；检查工作区，保留已有修改。
2. 先列本批实际调用链、输入/输出、写入位置及失败状态，确认没有另一个平行 owner。
3. 补一个能够在旧实现上失败的业务反例；隔离测试使用临时 HOT/WARM/COLD/Wiki/cwd，禁止连接真实模型和业务系统。
4. 修改最小范围，接口变更同步前端和生成类型；不把未实现的依赖替换成假成功。
5. 跑专项与适当的仓库质量门；核心路径改动执行完整核心检查。若隔离基础不可靠先修隔离，再跑全量。
6. 用实际入口演示结果，记录代码 revision、运行命令、数据范围、文件/SQL/HTTP 证据、未验证项。
7. 追加 DEV_LOG，只有满足本批退出条件才标 verified；测试失败或运行时未接通标 implemented/blocked 并写事实。

通用任务提示词：

```text
请执行 docs/v1.0/V1.0.0_CLOSEOUT_TASKS.md 中的 Cxx。
先核对当前代码与工作区，再完成本批实现和验收，不只输出建议。
遵守项目 AGENTS，保留其他改动；按实际业务入口验证。
不得用 mock/noop/seed/吞异常后空数据替代生产结果。
使用独立数据环境，记录真实运行时与模拟依赖的区别。
完成后报告：变更文件、修复前反例、修复后结果、回归、剩余风险。
达到本批退出条件后追加 DEV_LOG；未达到不得标 verified。
```

## 16. 运行维护交付清单

| 频率/事件 | 必需检查 | 失败后的动作 |
|---|---|---|
| 每次启动 | schema/环境身份/数据根/owned PID/API readiness/任务依赖 | 显示诊断；不消费未授权旧任务 |
| 每次新 Run | Skill版本、启停、授权scope、计划hash、预算、幂等键 | 拒绝或blocked，有明确理由 |
| 周期运行 | source到期/有效获取/游标、queue最老年龄、过期lease、outbox滞后、磁盘 | 暂停受影响writer/来源，保留重放数据 |
