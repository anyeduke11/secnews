# 停机链专项复盘 · R1-R17（2026-10-08 ~ 10-10）

> **一句话结论**：SIGTERM 停机从「无限排空需 SIGKILL」治理到「典型 1-3s 干净退出 + 全链有界 + 启动失败也体面」——17 项风险全部闭环，8 个工单（DEV-0301~0310），回归从 5320 → 5368 passed 零失败，每项都有实弹证据与契约测试防回潮。
>
> **接续指引**：细节台账在 `DEV_LOG.md`（DEV-0301~0310 逐单），运维标准动作在 `docs/RUNBOOK.md`「紧急止血」段；本文是三清单式收口快照，新会话凭本文 + DEV_LOG 即可接续，无需重翻聊天记录。
>
> **常用术语速查**：SIGTERM（系统「请你退出」信号，进程可从容收尾，区别于 SIGKILL「立刻死」不留收尾机会）；event loop（ asyncio 事件循环，FastAPI 的心脏，被冻住 = 整个服务卡住）；SSE（服务器单向长连接推送，前端心跳与 MCP 工具连接用，长连接天然「不收尾」是停机头号敌人）；executor join（Python 退出前要等后台线程任务做完，任务不结束进程就死不了）；WAL（SQLite 预写日志，退出前折叠回主库保证不丢）；pgid（进程组 ID，一次杀干净整棵进程树的抓手）；MCP（AI 客户端连本工作站的原生工具协议）。

## 一、已完成（按工单，每条四要素）

**1. 停机有界化根修（DEV-0301，含纠错前提）**
- 是什么：推翻「uvloop 不接管信号」误判（DEV-0297 旧记录），真根因 = uvicorn 排空超时无上限，SSE 长连接让「等连接收尾」永远等不完。
- 做了什么：取证端口立释证明信号其实到了 → 定位 `timeout_graceful_shutdown` 默认无限 → 两个入口（run.py / `main.__main__`）设 15s 有界。
- 结果：✅ 实弹 2s 干净退出（修复前 30s+ 需 SIGKILL）。
- 在哪看：DEV_LOG DEV-0301；`run.py` 注释「DEV-0301 根因修复」。

**2. SSE 停机哨兵前置 + watchdog 对称停机（DEV-0302：R1、R3）**
- 是什么：R1 = 前端事件流吃满排空预算；R3 = 知识库文件监视器只启动不关闭。
- 做了什么：时序两轮实弹踩坑后定型——哨兵包装 uvicorn 的退出处理函数，信号到达**先**通知所有事件流自行收尾（先于排空）；关闭链补 `stop_watcher()`。
- 结果：✅ 挂真实 SSE 客户端 SIGTERM **1s 退出 + 客户端收到终结帧**（修复前 17s / 0 帧）；`test_sse_shutdown.py` 契约在库。
- 在哪看：`backend/utils/sigterm_sentinel.py`、`backend/core/events.py`、`backend/api/events.py`。

**3. 退出尾闸 + 孤儿自动收割 + 一键重启（DEV-0303：R2、R4、R5）**
- 是什么：R2 = 后台线程任务能挂死进程退出；R4 = 强杀后残留子进程无人认领；R5 = 手工重启四步易错。
- 做了什么：`guaranteed_exit`（一切收尾做完后硬退出，跳过「等后台线程」环节）；启动闸识别残留进程组并**安全**自动清场（全员同用户 + 后端签名/锁产权双裁决，宁拒勿错杀）；`restart_backend.sh` 固化标准动作。
- 结果：✅ 停机典型 0.5-2.6s；孤儿残留下次启动自愈；SOP 单命令。
- 在哪看：`backend/utils/shutdown.py`、`backend/utils/instance_lock.py`、`scripts/restart_backend.sh`、RUNBOOK「紧急止血」。

**4. 健康探活超时治本（DEV-0304）**
- 是什么：启动追抓（catchup）在事件循环线程上直连数据库做同步读写，撞上写锁就把整个服务冻住最长 5 秒——health 偶发无响应。
- 做了什么：实验**证伪** GIL 假说（Python 3.14 数据库等待会放手）→ 锁定真因 = 循环线程自己卡在同步调用 → catchup 全部数据库操作挪到工作线程；两大热点段抽成整段函数一次过桥。
- 结果：✅ 全生命周期 90 笔连打零超时（中位 2-4ms）；线程落位有契约测试（断言「不在主线程执行」）防回潮。
- 在哪看：`backend/services/catchup_service.py` 注释 DEV-0304、`test_catchup_service.py` 尾部 2 用例。

**5. 停机总监时器——终极兜底（DEV-0305：R8、R9）**
- 是什么：尾闸虽好，但它挂在「uvicorn 正常返回」之后——R8（executor join 堵死返回路径）和 R9（关闭链某环节无限挂）都能让尾闸永远轮不到。
- 做了什么：信号到达时武装一个**后台计时器**（预算耗尽直接从旁路硬退出）——唯一穿透一切挂点的防线；与 R1 同哲学「不信任下游，先到先防」。关键取证：uvicorn 退出时会**重放信号**把进程直接杀死（源码 server.py L335-336），哨兵顺手吞掉重放，尾闸才能真正执行。
- 结果：✅ 复刻实验：30s 后台任务在跑 + 预算 4s → 4s 准点硬退 exit 0；生产日志 `guaranteed_exit: hard exit (code=0)` 可查。
- 在哪看：`arm_shutdown_deadline`（shutdown.py）、`_captured_signals` 清空（sigterm_sentinel.py）。

**6. MCP 长连接收编 + 收割放宽 + 催停有效化（DEV-0306：R10、R11、R12）**
- 是什么：R10 = AI 工具连接（MCP SSE）不吃哨兵，每次停机白等 15s；R11 = 孤儿组里没有「后端签名」进程时不敢收；R12 = 再发一次 TERM 其实没用（uvicorn 原生只认二次 Ctrl+C）。
- 做了什么：包装 MCP 库的连接处理（**必须保持「异步上下文管理器」形态**——首版按签名猜写成协程，生产 500 当场暴露，教训入档）；收割裁决加「锁产权」分支（锁文件登记的进程组 = 我们自己的，同用户即可收）；二次 TERM 即触发强制跳过剩余等待。
- 结果：✅ 挂 MCP 连接停机 **1.02s**（修复前 15s）；孤儿自愈覆盖纯子进程场景；催停真实生效。
- 在哪看：`backend/utils/mcp_sse_shutdown.py`（含 CM 形态契约测试）、`reap_conflict_group`。

**7. 预算联动 + 兜底武装 + 重放过桥（DEV-0307：R13、R16、R17）**
- 是什么：R13 = 总计时预算 60s 会被关闭链各子环节之和（65s+）挤兑，优雅收尾反被自家兜底抢杀；R16 = 多进程/直起入口没经过 run.py，等于裸奔；R17 = 事件流重连重放又一处循环线程直连数据库。
- 做了什么：预算改**派生和**（排空+drain+固定环节 30s，默认 75s，随子超时联动）；`backend.main` 模块导入期兜底武装哨兵（幂等）；重放查询过工作线程。
- 结果：✅ 实弹抓到最有价值样本——图谱点火在跑时停机：优雅走完但卡在后台下载 71s，派生 75s 预算**容纳**了自然退出（旧 60s 会抢杀）。
- 在哪看：`derived_shutdown_budget`（shutdown.py）、main.py L395 R16 注释块。

**8. 批任务协作让出（DEV-0308：R14）**
- 是什么：AI 分类/语义判别/自动入管三个批处理循环在停机信号到达后仍继续烧大模型调用：白花钱、拖长退出，且取证实锤 intake 的游标推进在「切一半」时会**静默吞掉未处理条目**（真数据丢失语义）。
- 做了什么：共享探针 `shutdown_yield_requested()` + 三批循环**条目边界**自检让出，按各自数据语义定自愈策略（下轮重扫零丢失 / 诚实留空 / 游标冻结）。
- 结果：✅ 真环境冒烟：生产库 50 条待判别候选在哨兵置位下零次大模型调用即收手；`test_shutdown_yield.py` 6 契约 + conftest 哨兵状态 per-test 隔离（全量首跑 10 例泄漏劫持的根修）。
- 在哪看：auto_classifier / info_filter_gate / auto_intake_service 三处 `DEV-0308 R14` 注释点。

**9. 启动失败也体面（DEV-0309：R15）**
- 是什么：uvicorn 在启动半程失败时**从不执行**关闭半程（源码可证），残留全靠「下次启动收割 + 进程退出兜底」——曾被判定留档不修，owner 点名实修。
- 做了什么：lifespan 拆成启动函数 + 关闭链函数 + 包装器——失败路径**先尽力跑完同款关闭链再传播原异常**（退出码 1 的报错语义不变）；链逐步幂等化（没启动的子系统 = 空操作）。
- 结果：✅ 注入启动失败实弹：`best-effort shutdown chain` 落日志 + 原异常传播 + 真实链对全未启动子系统安全跑通；契约测试 4 例。
- 在哪看：main.py `_run_startup` / `_run_shutdown_chain` / `test_startup_failure_teardown.py`。

## 三、增强和扩张（三问法，按优先级）

**1. 停机/让出指标化（P1）**
- Why：现在验证停机快慢靠人肉掐表 + grep 日志；预算是否被逼近（如 71s/75s）无告警——一旦未来关闭链新增慢环节把预算顶穿，要等到硬杀事故才暴露。复发概率中、损失 = 一次不可解释的「服务没关干净」。
- What：把三数落表——每次停机耗时、deadline 是否触发、批让出次数（shutdown_yield 计数），供 /settings 观测区展示。
- How：log_event 已在关闭链埋点（drain done / hard exit），补停机总耗时与 yield 计数两个结构化事件 + 聚合查询 + 观测卡；工作量级 = 小时（复用 observability 既有链路，无新表必要则更省）。

**2. 批任务全盘点巡检（P2）**
- Why：R17 与 DEV-0304 都是「普查后仍有漏网」（SSE 重放、catchup）——同类「循环线程直连数据库/烧 LLM」写法会随新代码再生，靠人工复盘不可持续。
- What：自动化检查器：扫描 services/scheduler 层在 async 函数体内直接调用同步 repo/LLM 符号的代码（静态 AST 级）。
- How：并入 `scripts/generate_meta.py --check` 同类 CI 门或独立 `check_blocking_calls.py`（scripts 命名规范已有 check_* 类）；白名单豁免存量；工作量级 = 天。

**3. 重启 soak 回归（P2）**
- Why：全部实弹都是 N=1；停机链的分层兜底（哨兵/排空/drain/尾闸/deadline/收割）组合路径多，一次成功不代表十次稳定——DEV-0293 双实例事故正是「平时都对，偶发即灾难」型。
- What：循环「重启 → 健康检查 → 端口/进程树断言全清 → 账本无悬账」50 次的脚本化 soak，夜间跑。
- How：基于 restart_backend.sh 包一层断言（ps 组检、health 200、hotspot.lock 覆写、run 账本 outcome 完备性 SQL 校验），出报告；工作量级 = 小时级脚本 + 一晚机时。

## 四、协作纪律沉淀（本项目实例印证）

1. **不可观测组件先建可观测再修**——R1 时序两轮「改了但还是 17s」，靠「客户端收帧计数」探针一轮定位（排空在 lifespan 之前）；R2 尾闸「明明装了却不执行」靠日志缺失 + 源码取证锁定信号重放。

3. **部署 ≠ 送达**——启动闸代码（R16/DEV-0310）装载需下次重启才生效，台账如实标注「非必须重启」而非谎称已生效。

5. **兜底预算要被子超时之和「容纳」**（本批新增）——分层超时的独立性是幻觉（R13）：派生联动优于拍脑袋常数，71s/75s 样本实证。
