## 2. 根因（与 v0.8.8 当时的归因不同）

v0.8.8 C5-7 当时的归因是「R-15 四段指挥台新增量对冲了删除量」——**该归因不完整**。实测产物构成后真因是另一件事：

| chunk | gzip | 占总量 |
|---|---|---|
| `vendor-echarts` | **384,512 B** | **52%** |
| `vendor-react` | 53,733 B | 7% |
| `index` (主 chunk) | 27,132 B | 4% |
| 其余 71 个产物 | 280,000 B | 37% |

**单是 echarts 一项就占全包的一半**。根因链：

1. `echarts-for-react` 默认入口硬编码 `import * as echarts from 'echarts'` → 整包 echarts（含 map / 3D / 全部 chart 类型）进 vendor chunk；
2. 全仓仅 3 处用 echarts，实际只用 4 种 chart（gauge / graph / line / bar）+ 4 个 component；
3. `vite.config.ts` 的 `manualChunks` 又把 `echarts` 整包 pin 进 `vendor-echarts`，进一步固化。

即：**R-15 的新增量只是"最后一个稻草"，真正的杠杆在依赖引入方式**。此前连续多轮靠"删文件减包体"收效有限，是因为减的都在长尾（单个组件几千字节），而头部 384KB 从未被触碰。

## 3. 修复

### 3.1 新增统一入口（唯一允许 import echarts 的地方）

`frontend/src/components/shared/EChart.tsx`：

```ts
import ReactEChartsCore from 'echarts-for-react/lib/core';
import * as echarts from 'echarts/core';
import { BarChart, GaugeChart, GraphChart, LineChart } from 'echarts/charts';
import { GridComponent, LegendComponent, TitleComponent, TooltipComponent } from 'echarts/components';
import { LabelLayout } from 'echarts/features';
import { CanvasRenderer } from 'echarts/renderers';

echarts.use([BarChart, GaugeChart, GraphChart, LineChart,
              GridComponent, LegendComponent, TitleComponent, TooltipComponent,
              LabelLayout, CanvasRenderer]);
```

**依据**：`echarts-for-react` 官方 README「按需引入」章节给出的正是
`import ReactEChartsCore from 'echarts-for-react/lib/core'` + `import * as echarts from 'echarts/core'`
组合 —— 本实现与官方推荐一致，非自创姿势。

`echarts-for-react/lib/core` 不引全量 echarts（允许注入自定义实例），`echarts/core` 提供 `init`/`use`。

### 3.2 三个消费方改引统一入口

| 文件 | 原 | 现 |
|---|---|---|
| `components/MasteryGauge.tsx` | `import ReactECharts from 'echarts-for-react'` | `import { EChart } from './shared/EChart'` |
| `components/KnowledgeGraph.tsx` | 同上 | `import { EChart } from './shared/EChart'` |
| `components/knowledge/KnowledgeCompoundingDashboard.tsx` | 同上 | `import { EChart } from '../shared/EChart'` |

**功能面零变更**：三处 option、事件绑定（`onEvents.click`）、样式全部逐字保留。

### 3.3 vite.config manualChunks 跟随

`manualChunks` 按模块 id 前缀匹配，实际 import 由 `echarts` 变为 `echarts/core` / `echarts/charts` / `echarts/components` / `echarts/features` / `echarts/renderers`，pin 必须同步改，否则 echarts 被拆散进多个 async chunk（图表页反而多发请求）。

### 3.4 注册面完整性守卫（新增）

**风险**：echarts 对未注册的 series 走 `lib/model/global.js` 缺件分支 —— `error("Series gauge is used but not imported...")` 后**静默跳过该 series**（不抛异常、不产生 view → 图表空白）。将来新增图表类型却忘了注册，将表现为「图表空白」且**零编译错误、零测试失败**。

守卫两件套：

1. **`frontend/src/components/shared/EChart.test.tsx`（4 用例，CI 门禁）**
   - 直接引用**生产注册面**（`EChart.tsx` 导出的 echarts 实例），不另建注册；
   - 捕获 `console.error` 断言三类生产 option 无缺件消息；
   - 另有一条覆盖**组件接线**（注入实例是否真被 `echarts-for-react/lib/core` 接受）。

   **消融验证**（关键，见 §4）：仅断言 `not.toThrow` 的版本在缺件时**照样通过**（消融 1 失败）→ 改为捕获 `console.error` 后消融**如期失败** → 断言真正有效。

2. **`scripts/verify_echarts_bundle.mjs`（一次性脚本，不接 CI）**
   真 Chromium 加载 **`frontend/dist/` 生产产物**，dynamic import 生产 chunk →
   用生产注册的实例 init → setOption 三类图 → 断言 (a) 无缺件报错 (b) **canvas 真的画出了元素**。

   **WHY 需要**：tree-shaking + CJS interop 组合的典型失效是「build 通过、运行时白屏」——
   单元测试跑的是源码（vite dev transform），与生产产物（rollup chunk 边界 + CJS→ESM interop + 真实 canvas）不是同一份代码。

## 4. 消融验证（证测试非空转）

| 消融 | 预期 | 实测 |
|---|---|---|
| 从注册面去掉 `GaugeChart` | 守卫测试失败 | ✅ 失败（`expected [ Array(1) ] to deeply equal []`，捕获到 `Series gauge is used but not imported`） |
| 恢复 `GaugeChart` | 守卫测试通过 | ✅ 3 passed（补组件接线用例后 4 passed） |
| 生产产物（真实 Chromium） | 三类图 canvas 均已绘制 | ✅ `gauge / graph / line+bar` 全部 `canvas 已绘制=true` |

**注**：首版守卫用 `expect(() => inst.setOption(...)).not.toThrow()` —— 消融时**仍然通过**，说明该断言抓不到 echarts 的静默缺件。改为捕获 `console.error` 后消融才如期失败。这是本次唯一一处「先写测试、后发现测试无效并重写」的地方，**如实留痕**。

## 6. 遗留与已知边界

1. **echarts chunk 内仍含未用图表类型**（sankey / treemap / sunburst / pie 等约 213KB gzip）：
   `echarts/charts` 桶文件的 `export { install as XChart }` 形式 + echarts `package.json` 的
   `sideEffects: ["lib/chart/*.js", ...]` 使 Rollup 无法摇掉未用的 chart 实现。
   再压需绕过公开 API 直接引 `echarts/lib/chart/*/install.js`（非公开路径，升级易碎），
   **且当前余量 155,688 B 已远超目标** → 按「够用即止」不做，登记为可选后续项。
2. **新增图表类型必须同步两处**：`EChart.tsx` 的 `use([...])` 注册面 + `EChart.test.tsx` 的守卫用例。
   漏注册 → 图表空白（echarts 静默跳过），守卫测试会红。
3. **T8 三主题人工走查仍未闭**（v0.8.8 门 10）—— 与 M-4 无关，仍待 owner 目视。
