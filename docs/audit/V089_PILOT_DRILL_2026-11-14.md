## 演练矩阵（6 步全部达成）

| 步 | 场景 | 期望 | 实测结果 | 判定 |
|---|---|---|---|---|
| 1 | **基线**：plan 内合法命令（读 `src/input.txt`） | 沙箱不能瘫掉正常功能 | `ok=true`，stdout=`source material`，run `run_INH572KWZZFSUSX3R6VQRRCAD7` | ✅ |
| 2 | **写越界**：argv 合法（python 在白名单内），但写 workspace **外**（仓库根 `p5_escape_probe.txt`） | 内核拒绝 + 文件不产生 | `reason_code=E_COMMAND_FAILED`，`escaped_file_created=false`，stderr=`PermissionError: [Errno 1] Operation not permitted` | ✅ |
| 3 | **读凭据**：读仓库根 `.env`（绝对路径） | 内核拒绝 | `denied_by_sandbox=true`，stderr=`PermissionError: [Errno 1] Operation not permitted: '/Users/duke/Documents/hotspot/.env'` | ✅ |
| 4 | **出网**：`socket.create_connection(('example.com', 80))` | 系统层断网 | stdout=`NET-BLOCKED gaierror` | ✅ |
| 5a | **ulimit CPU**：死循环 | 内核 SIGXCPU 杀进程 | `rc=-24`，`killed_by_sigxcpu=true` | ✅ |
| 5b | **总预算超时**：`sleep(30)`，`command_timeout_sec=1` | wall 超时收口 | `reason_code=E_COMMAND_TIMEOUT` | ✅ |

> **步骤 2 的意义**: argv 在白名单内、plan 也已审批 —— L2 声明层**拦不住**它。这正是 P5 的价值：同一命令在系统层被内核拒绝。
> **步骤 5a / 5b 是两条独立机制**: 5a 是内核资源限额（SIGXCPU），5b 是执行体 wall 超时（`E_COMMAND_TIMEOUT`）。两者独立可验。

## 演练④ 暴露并修复的两个真实缺陷

1. **全局 cooldown 吞掉跨 run 越界**（违反「失败必可见」）：`observability_alerts` 的 cooldown 语义是「同 (metric, level) 在窗口内只发一条」。执行体越界沿用该语义时，**6 次真实越界只落 1 条告警** —— 第二个 run 的越界被静默抑制。
   修复：`observability_alert_service.fire_alert` 新增 `dedupe_key` 参数（默认 None = 保持 v0.7 既有语义不变）；执行体传 `dedupe_key=run_id` → 同一 run 内重复越界合并（防刷屏），**跨 run 的真实越界各自可见**。修复后演练④ 落 2 条（对应步骤 2 / 3 两个不同 run）。
2. **CPU 限额与 wall timeout 同值 → 内核限额永远不触发**：执行体原本 `timeout=command_timeout_sec`，而 `RLIMIT_CPU` 也取 `command_timeout_sec` —— wall 超时总是先到，内核 SIGXCPU 形同虚设（步骤 5a 首跑实测得 `E_COMMAND_TIMEOUT` 而非 `rc=-24`）。
   修复：wall timeout 改为 `command_timeout_sec + 2s` **信号投递宽限**（`_CPU_SIGNAL_GRACE_SECONDS`），总预算 `total_timeout_sec` 仍是硬上限（min 取严）。

## 已知限制（如实）

1. **仅 macOS 生效**：`sandbox-exec` 是 macOS 专有。非 macOS（如 CI ubuntu-latest）→ 降级为「仅 ulimit」，**不假装有沙箱**（`audit_log` 留痕 `sandbox=unavailable` + warning 日志）。生产部署若为 Linux，需另加容器隔离（P10 遗留项，Docker 留后续）。
2. **host 级出网白名单不可表达**：macOS Seatbelt 不支持 `(remote ip "1.2.3.4:443")`（内核拒 "host must be * or localhost"）。故 `plan.network` 非空时**仍全禁** —— 放行全集等于放行任意 host，违反「更严不放松」。需要出网的 plan 目前无法通过 L3 放行（须人工绕开沙箱，属后续能力缺口）。
3. **`RLIMIT_AS`（内存）不可用**：macOS 内核拒绝收紧 AS（`current limit exceeds maximum limit`）。内存上限未实现 —— 现状靠 CPU 限额 + wall 超时 + 沙箱约束间接兜底。Linux 下可设，本期未做。
4. **解释器路径需显式放行**：venv 常在仓库内，会被仓库级 deny 挡住 → 解释器启动需 `subpath` 放行解释器目录 + `literal` 放行每一级祖先目录（实测：解释器启动时调 `realpath()` 解析自身路径，缺任一即 `Operation not permitted`）。该放行**只针对解释器路径**，不放行仓库其余内容。
5. **读隔离用「定向 deny」而非白名单枚举**：`(deny default)` + `file-read*` 子路径白名单会让 CPython abort（exit 134，需读 stdlib / dylib / 动态链接缓存）。故系统读 blanket 放行、读收窄靠 `deny 仓库根 → deny workspace 根 → allow 声明子目录`（Seatbelt **last-match-wins**，顺序即语义）。副作用：仓库外的系统文件（如 `/etc/hosts`）仍可读 —— 边界目标是「计划外的项目数据与凭据」而非全系统只读。
