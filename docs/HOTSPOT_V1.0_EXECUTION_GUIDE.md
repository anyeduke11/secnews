# Hotspot v1.0 新手开发执行指南

> 日期：2026-09-05；全部任务初始状态：待实施。
> 配套：[总体方案](HOTSPOT_V1.0_DEVELOPMENT_PLAN.md)、[产品 PRD](HOTSPOT_WORKSTATION_PRD_V1.0.md)、[设计审查](HOTSPOT_V1.0_DESIGN_REVIEW.md)。
> 本文是未来交给编码 Agent 的任务书；本次没有执行这里的安装、代码修改、数据库迁移、模型调用或发布步骤。

## 1. 你和编码 Agent 如何分工

你负责提供真实工作问题、识别结果是否有用、审阅范围与成果。Agent 负责读代码、实现、测试、记录；它应把证据展示给你，不能只说“已完成”。没有解决的工程失败由 Agent 继续定位，不要求你凭空决定技术细节。

每次推进一个任务卡的小步骤。以下词语在本项目中的含义：

| 术语 | 在本项目中要观察什么 |
|---|---|
| 基线 | 改之前代码版本、真实数据路径和已知问题的清单 |
| 分支/提交 | 可追溯的代码变更记录；不会自动备份数据库 |
| 隔离环境 | 测试只写自己的临时库、Wiki 和日志，不碰你的资料 |
| 契约 | 页面与后端共同遵守的字段、状态和错误约定 |
| 幂等 | 同一个请求重复到达，也只产生一次预期结果 |
| 租约 | 某个工作进程在一段时间内拥有任务；过期后需核对再接管 |
| 回执 | 能证明实际执行、保存或验收结果的持久记录 |
| 回填 | 将旧记录按规则关联到新模型，并保留原 ID |
| 发布门槛 | 未通过就不能称正式版本完成的验收项 |

## 2. 每轮固定工作方式

1. 让 Agent 读取 AGENTS、PROJECT、PROGRESS、DEV_LOG、CHECK_LOG 和当前任务卡；检查实际 HEAD 与未提交修改。
2. 让它说明本小步修改哪些文件、依赖是否已满足、准备验证什么。现有未提交内容不能随意清除。
3. 实现一个可验收结果。复杂任务先按卡片中的 1/2/3 小步骤逐轮做，不同时改完前后端、数据库和运行时全部层。
4. 验证正常情况，再验证卡片指定的失败情况；修复失败原因后重测相应范围。
5. 在界面或验收日志看真实结果；记录 commit、测试、产物、未解决问题到任务状态与 DEV_LOG。
6. 仅在本小步验收通过后继续下一步。若需要外部资料、真实模型或生产切换，Agent 先完成隔离准备并明确剩余动作。

代码提交遵循仓库显式 pathspec 规则；不要 `git add -A` 收入无关数据或密钥，不使用 destructive reset 清掉未知修改。文档中的拟定脚本必须由对应任务实现并验证后才运行。

## 4. 详细任务卡

### T00 建立真实基线和迁移账本

**目标与输入**：确认到底从什么状态迁移。读取四份附件、当前代码版本和现有配置解析逻辑；旧审查数值只作历史线索。

1. 检查 HEAD、未提交修改、启动方式、版本来源、运行组件和依赖；登记旧代码与待建能力，说明 frontend package 版本是否用于产品显示。
2. 只读盘点数据库/Wiki/session/log/密钥恢复材料的路径和 owner；先不跑现有 backend 测试，不输出密钥内容。
3. 建立功能/路由/数据/20 Skill 清单和任务台账，给每项旧功能标保留、适配或后置入口；后置不表示删除。

**交付**：拟定 `docs/v1.0/baseline.md`、`docs/v1.0/task-status.md`、旧功能清单；一条固定样本漏洞工作故事。拟定路径仅在执行本任务时创建。

**通过证据**：APP_VERSION 和实际启动入口明确；每个数据根及写入者可定位；没有把 v0.8.3 标已实现。你能指出第一条要做的真实工作及完成条件。

**失败/回退**：发现基线变化先调整清单，不覆盖现有修改；本任务为只读核对和文档，无数据回退。

### T01 先修测试隔离与虚假成功证据

**目标与范围**：消除旧审查 F13 的已知风险。主要涉及测试 bootstrap/conftest、观测写入和测试专用配置。

1. 在导入生产模块之前，为 HOT/WARM/COLD、Wiki、日志、dsh/pi home 配置临时根；禁止普通测试出网，生产路径命中立即报错。
2. 检查未申请 temp_db 的 agent_bridge 测试，加入对应隔离；测试不得依赖用户机器上的真实数据库。
3. 用哨兵生产目录和临时数据证明错误路径被拒绝；再跑原来有副作用的定向测试，建立隔离后的回归基线。

**交付**：隔离 fixture、路径防护、测试策略说明及实际验证日志。

**通过证据**：测试确实覆盖观测 helper、三库与子进程目录；真实资料未被写入。在线系统同时写库时不以库 hash 变化直接归罪测试，应在受控副本/哨兵环境证明隔离。

**新手验收**：让 Agent 展示测试数据写到了哪个临时目录。若只答“mock 了模型”，不算通过。

**失败/回退**：停止扩大测试，继续修隔离；保留历史可疑记录，不自动删除 `agent_runs` 数据。

### T02 建立备份、恢复与开发副本

**输入与范围**：T00 写入者清单、T01 隔离；现有 backup 服务和脚本先复用。

1. 在副本验证停写、排空、SQLite backup API、Wiki/session 文件快照和加密恢复材料清单。不得打印恢复秘密。
2. 恢复到新目录，检查事务事实、原文、产物与知识引用；记录实际 RPO/RTO，而非只做 integrity_check。
3. 配置独立开发数据根，关闭自动出站/外部副作用；端口冲突使用明确的测试端口，不改默认生产配置。

**交付**：备份 manifest、恢复报告、开发环境配置模板；拟定的迁移工具必须默认 dry-run。

**通过证据**：另一目录能打开完整资料链；旧系统仍可用；没有明文密钥进入 git。

**新手验收**：随机选一条收藏和一篇知识，在恢复副本打开并检查出处。

**失败/回退**：不迁移真实数据；修备份再演练，旧环境保持原状。

### T03 固定领域契约和最小交互原型

**输入与范围**：PRD F01-F12、本文总体方案 §5；Pydantic/API 契约、前端路由原型和现有 schema。

1. 对照旧表定义 Case/Subject/Judgment/Action/Run/Artifact/Knowledge 和 revision；明确每种状态及 allowed_actions。
2. 定义标准输入输出/错误/幂等/CAS/SSE schema；建立生成 TS 的确定性脚本与漂移检查，先用小接口验证。
3. 做四入口和事项详情的最小交互原型，明确标识测试数据；走查缺资产、待验收、失败三个路径。

**交付**：拟定 `docs/v1.0/contracts.md`、可生成类型、原型和数据归属决策；不要求一次完成全量 SQL。

**通过证据**：UI 和后端状态枚举一致；你不需要复制资讯到聊天框就能进入事项；“运行结束”和“工作验收”各有独立位置。

**失败/回退**：原型不接生产默认入口；调整契约再继续，避免带歧义写完整业务。

### T04 尽早验证真实上游能否协同

**输入与范围**：T03 最小模型/工具契约；vendor 源码、runtime 适配和隔离探针。候选 SHA 见总体方案 §4.2。

1. 固定上游 commit、工具链和许可证；在干净目录构建官方 SDK，记录依赖与产物 hash。
2. 使用官方 dsh stdio SDK、pi AgentSession；连接隔离工具返回已知产物，验证请求、结果、error、cancel 和 session 身份。
3. 在有明确模型配置/额度的测试环境走真实 dsh→pi→工具→回执；验证 ai_hub 能保留工具消息。单纯 fixture 测试只标 protocol-tested。

**交付**：构建锁、最小适配、协议兼容报告、真实调用 trace。拟定 worker 协议不冒称上游原有协议。

**通过证据**：回执含 dsh/pi commit、session、tool_call_id、产物 hash；只有文本的输出无法通过。并发配额为 1 时能结束。

**新手验收**：让 Agent 展示真正执行的工具、得到的文件和对应日志，不能只看“模型回答正常”。

**失败/回退**：固定失败版本和协议差异，修适配或选明确的新 SHA 重测；不降级 mock 后宣布源码整合完成。

### T05 先打牢证据提交和故障恢复

**输入与范围**：T02、T03；WikiFs、HOT 回执与可重建索引。

1. 实现 evidence/revision、hash、路径约束，保留旧 Wiki 根；用唯一提交键建立 intent。
2. 实现临时写、原子 rename、投影、receipt/outbox；只让完成提交进入发布查询。
3. 在 intent/rename/投影/receipt 前后分别注入中断，恢复重试；验证外部手工修订产生新版本。

**交付**：统一提交服务、增量迁移、恢复器和故障测试；后续 collector/Skill 只能走此入口。

**通过证据**：相同提交重试只有一个可见版本；写失败无虚假文件链接；旧引用仍指旧 hash。

**新手验收**：模拟一次保存失败，应看到“未保存/可重试”，而非绿色完成。

**失败/回退**：停新发布保留 intent；不删旧正文、不自动清理待恢复文件。

### T06 统一源抓取并开始稳定性观察

**输入与范围**：T05；collection/source_scheduler/collector/parser/源统计。

1. 把定时、手动、重试接到同一源任务；不可变 FetchRequest、source 租约、域名限流和游标。
2. 统一 fetched/parsed/eligible/persisted/new；落库失败不成功，watermark 不越过未处理失败批次。
3. 覆盖 304、429、超时、200 错页、分页重叠、重启恢复；接入首批关键源并展示实际状态，开始 7 天观察。

**交付**：源级管道、保存样本的 parser 回归、实际健康 API/最小页面。

**通过证据**：两个源并行时一源超时不阻塞另一源；同源无重复写；停机到期任务进入调度分母。最终覆盖试点锁定关键源名单。

**新手验收**：挑一个正常源和一个故障源，看最后有效时间与下次重试，不以“启用”替代健康。

**失败/回退**：可按源暂停新调度；不能回退到已知吞持久化异常的旧写路径继续宣称健康。

### T07 建立收录门槛和事件流

**输入与范围**：T06；quality_hook/info_filter、资料池、聚合、价值样本。

1. 基础准入与岗位精选拆开；异常入 quarantine，保留原文、规则版本、理由和重评入口。
2. 合并转载但保留官方更新/撤回；支持待核实关键首报、暂缓、关注和加入事项。
3. 建立 >=200 条分层标注及独立关键事件参考集；调参和留出分开，先测基线再锁阈值。

**交付**：准入服务、事件 API/页面、样本与评测定义。

**通过证据**：关闭个性化 Skill 不绕过基础门槛；官方短公告不被统一字数规则误拒；重大更新不被去重丢失。

**新手验收**：逐项说明为什么某条进入精选、某条待核实；不能只显示一个无法解释的高分。

**失败/回退**：停止正式精选或退到已验证规则版本；原始资料继续保存可重评。

### T08 关注对象与工作事项落地

**输入与范围**：T03/T05；新 case 服务/repo/API 与旧 TODO/资产关联。

1. 实现岗位上下文及 CSV/JSON 导入预览、错误行反馈、subject revision；不要求先填完资产才能用。
2. 实现研究/影响研判/行动跟进模板，绑定不同完成条件；事件创建事项自动继承出处，重复事项提示关联。
3. 实现事项列表和详情骨架，支持证据追加、暂停/取消/关闭原因及版本冲突。

**交付**：对象/事项 API、增量 schema、最小详情和导入测试。

**通过证据**：补资产只影响新判断；重复请求不建两张事项；纯研究事项不被强迫执行。

**新手验收**：一条资讯进入事项后不用再次贴全文，能找到目标、证据与下一步。

**失败/回退**：关闭新建入口，保留已有事项可读；不把旧 TODO 批量重写。

### T09 让入队任务真正执行

**输入与范围**：T01/T03/T05；trigger_gate、skill_runner、lifespan、ToolRegistry。

1. 显式注册 handler、启动/关闭唯一 worker；202 返回真实 run/ticket 身份。历史 pending 放 legacy_hold。
2. 原子 claim、租约 generation、deadline、幂等键、attempt 和工具回执；旧 worker 回写必须 CAS。
3. 用确定性受控工具做 HTTP submit→执行→产物→回执→状态 E2E，再测重复提交、失联、超时和取消。

**交付**：运行协调器与事件 API；复用已有运行表，适配旧直接执行入口。

**通过证据**：新 ticket 必须关联 run；失败 handler/HTTP 错误不算成功；缺终态不会被自动成功；无授权旧票据不执行。

**新手验收**：点击运行得到可刷新恢复的任务详情，真实失败能看到原因。

**失败/回退**：停新 claim，核对已执行工具再决定恢复；不清空队列解决积压。

### T10 将 dsh/pi 接入生产运行契约

**输入与范围**：T04/T09；dsh、agent_bridge、runtime、ai_hub、ToolRegistry。

1. 把探针适配为受管生命周期、只读就绪检测和能力状态；dsh 拥有计划，旧 PLAN/REFLECT 保留历史兼容不再参与认知。
2. ai_hub 增工具消息/usage/cancel/能力选择；额度含排队，分层重试，工具产生效果后禁止透明重放。
3. 限定 pi ResourceLoader、工具、目录、环境与委派深度；abort 后超时终止进程组，核对回执与未结束子进程。

**交付**：可受管的真实源码运行时、就绪/不可用原因、配额与取消测试。

**通过证据**：session-only、中间文本后 error 均不能成功；SDK 失联显示 interrupted；并发 1 不死锁；网页指令无法增加工具权限。

**新手验收**：关模型后抓取/检索仍可用，依赖模型的任务明确说明不可用，不伪装完成。

**失败/回退**：按能力关闭新运行时入口，保留只读资料工作；不让纯文本 fallback 承接执行任务。

### T11 形成有证据的判断

**输入与范围**：T07/T08/T10；判断 schema、证据检索、dsh prompt/工具与审阅 UI。

3. 覆盖缺版本、证据冲突、公告撤回、无支持 claim、人工并发修订；完成 SK-02 主路径。

**交付**：判断服务和事项判断视图、黄金案例与真实调用记录。

**通过证据**：不存在“缺资产→不受影响”；不能仅凭引用存在判 claim 正确；旧版本随时可打开。

**新手验收**：每个关键结论点开原文都能解释其依据，也能看到不知道什么。

**失败/回退**：保留草稿并转 needs_evidence/disputed；不发布为已验证知识。

### T12 受控行动、产物与业务验收

**输入与范围**：T11/T10；Action、approval、artifact、acceptance 与 pi 工具。

2. pi 核对授权资料并生成影响矩阵/排查清单；工具回执与 hash 通过验证后，运行结束、行动待验收。

**交付**：SK-03、行动详情与验收 UI、断点/重复效果/产物失败用例。

**通过证据**：删除模拟产物或注入保存失败不能标完成；生成清单不等于完成排查；未知外部效果不得自动重放。

**新手验收**：先看“材料准备完成”，再上传实际结果并独立验收，观察事项完成条件如何满足。

**失败/回退**：取消新步骤、保留已有回执；回退代码不会撤销实际操作。

### T13 经验发布、复用与知识到期复查

**输入与范围**：T05/T12；Wiki、索引/事件实体、知识发布、复用回执。

2. 复用现有 chunks/实体做 FTS + 有界事件扩展，返回原文和理由；实现新事项条件比较与采用/效果回执，覆盖 SK-05。

**交付**：知识服务、经验详情、第二次任务完整演示、至少首批复用/不适用样本。

**通过证据**：旧经验可召回但条件不同会提示；withdrawn 不作为当前高置信依据；运行日志不能自动进入 verified。

**新手验收**：第二次任务少重复取证，同时能指出哪些旧方法仍可用、哪些旧结论不能照搬。

**失败/回退**：关新发布/自动复用，保留原文与人工搜索；重建派生索引不动事务事实。

### T14 六能力固化与启停

**输入与范围**：T13；skill_registry/runner、受管 manifest、版本和自动化设置。

**新手验收**：不用重写 prompt 即可运行；停自动化不误停全部手动操作；历史结果仍能查看。

**失败/回退**：将新请求锁回已验证版本，保留旧版本与历史；不能热改线上 prompt 影响在飞任务。

### T15 四入口与前后端一致性收口

**输入与范围**：T03 原型及各业务增量；现有 apiFetch/i18n/routes、Query、SSE 和真实聚合。

1. 早期随 T06-T08 接情报/事项页面；T11-T14 接判断、行动、验收、经验、能力；每次只迁一个页面/对象。

**交付**：四主入口、共享类型与查询缓存、持久状态事件、可操作的空/错/陈旧状态。

**通过证据**：两页同事项状态一致，刷新不丢运行；待办数字可追到实际对象；错误不是零；390 宽度关键动作可达。

**新手验收**：同时打开两个页面运行任务，断网重连后都显示同一真实结果；证据、讨论、产物不会互相遮挡。

**失败/回退**：新入口 gate 关闭，旧入口通过兼容 API 工作；不因切 UI 丢新任务。

### T16 迁移旧数据与旧功能

**输入与范围**：T02/T08/T13/T15；旧 schema/ID/文件/路由清单，新增回填脚本和兼容适配。

3. 核对 ID 集合/hash/用户状态/引用/孤儿，重跑应无新增重复；按旧路由含 query/hash/深链接回放原工作。

**交付**：迁移脚本、机器可读报告、人工抽样清单、20 ID 兼容矩阵与路由矩阵。

**通过证据**：无旧 ingested 删除；缺依据未标 verified；历史 pending 没被自动执行；每个旧功能有去向和验证。

**新手验收**：分别找旧收藏、TODO、知识和运行历史，用原入口和新入口核对；不是只比较总行数。

**失败/回退**：停止该批回填；通过 batch 记录定位，不删除原记录。副本重做可行，生产不能拿旧备份覆盖新写入。
