## 1. 定位

hotspot 的 AI 能力不是 chatbox, 而是**固化为主面板可启停的功能卡片**:

- **Skill (内置 20 + 用户可建)**: 单原子任务, 一键启停 + 跑一次 + 历史回放 + 反馈回写
- **Playbook YAML (Phase C)**: 多步编排 (skill → api → condition), cron/webhook 触发
- **触发器 (非聊天)**: 手动按钮 / cron / webhook / KL T1-T5 事件 / collector failure, 全部经 **trigger-gate** 单一入口排队

## 2. 架构分层 (v0.8 新增部分)

```

```

## 3. trigger-gate (A1 已交付)

- **单一入口**: `TriggerGate.submit(target_type, target_id, priority, source, user_id, inputs)` → TriggerTicket
- **限流**: 双层令牌桶 — per-user 60/min + global 600/min, 超限 `ThrottleExceededError` → API 429
- **持久化队列**: `trigger_tickets` 表 (WAL, 崩溃不丢; 状态 pending/running/done/failed)
- **三档优先级**: REALTIME(手动/webhook) > NORMAL(KL 事件) > BATCH(cron) — **仅出队排序, 非抢占** (运行中任务绝不中断, R6)
- **TriggerWorker 出队泵**: 守护线程 1s 优先级轮询 → Semaphore(3) 并发上限 → 派发可注入 handler; 启动时 reset_stale_running 崩溃恢复
- Phase A handler 为 no-op 占位 — **skill 执行接线归 B5**

## 5. API 契约 (A3 已交付)

**前缀 `/api/skill-registry`** (既有 `/api/skills` 被 Phase 41 书签 CRUD 占用, 按 info_filter kebab 先例裁决):

| 端点 | 语义 |
|---|---|
| GET `/api/skill-registry?category=&enabled_only=` | 列表 (不含 prompt 全文, has_prompt 标志) |
| GET `/api/skill-registry/{id}` | 详情 (schema + C/D prompt) |
| POST `/api/skill-registry/{id}/enable` / `disable` | 写 settings.kv |
| POST `/api/skill-registry/{id}/run` | **预注册态**: trigger-gate REALTIME 入队 → {ticket_id} (执行归 B5) |

错误信封 `{detail: {message, code, hint}}` 三字段必填 (P3-2); 404 SKILL_NOT_FOUND / 409 SKILL_DISABLED / 429 THROTTLED (附 retry_after_seconds)。
