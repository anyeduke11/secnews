## 1. 任务分解 (按序执行, 单人带宽)

### C — KPI 口径切换 (半天, 观测面 + 文档)

**裁决依据**: 转化率带与质量门槛结构性不可兼得 (DEV-0281/0284); 行业头部量「分诊时延」(Gemini Triage 30min→60s) 非流量比率 (P2-6)。

- 新增观测指标: ①`signal→case 时延` (v1_signals.created_at → 关联 case.created_at, P50/P90); ②`artifact 产出率` (v1_runs done 且 artifact≥1 / runs total, 7d); ③保留 signals/hotspots 比率但**降级为参考值** (不再设带)
- 挂载: `/api/ops/kpi` (或扩 observability_router) + PRD §1.4 成功指标行同步改写
- **验收**: 新指标可查; PRD 成功指标不再含「15-30% 带」表述; 旧比率仍可算但不作为门

### D — gate 限频预算调参 (半天, 配置 + 观测)

**现状**: gate_detect 失败 398/24h ≈ 全部调用被限频 (rate_limited), AI 内容检测实际空转; gate_rate 逻辑在 AIService (限频标记内存态)。

- 取证: 现行预算值 (gate_rate_allowed 实现) × 调用量 → 定新预算; 敏感度: sensenova 成本档 (flash-lite) 可承受上调
- 改配置/常量 + 观测面补 `gate_detect.limited` 计数 (fails_by_scene 已有, 补 ok 率趋势)
- **验收**: 24h 窗 rate_limited 占比 <20%; ok 调用量可见上升; 成本无报警

### E — HOT db 数据治理 (半天)

**现状**: hotspot.db 130MB > 80MB 阈值 (巡检 FAIL)。

- 取证: 表体积 TOP (sqlite dbstat 或逐表 count×行宽); 识别可清理面 (api_events / audit_log / admission_log / 过期 hotspots?)
- 执行: maintenance vacuum + retention 策略落 maintenance job (若缺); 阈值本身可校准 (80MB 是否合理? 单机盘充裕可放宽至 200MB 并留档理由)
- **验收**: 巡检 OK (或阈值校准后 OK 且有据); retention job 注册可查

### B — MCP server 导出 (1 天, 只读查询面)

**裁决依据**: P2-6 行业 7 模式对照差距①; mcp gate 管道现成 (server 本体 is_mcp_enabled, 调试路由已存)。

- 范围 (**只读**, 不暴露写): run 查询 / proposal 查询 / case 查询 / artifact 查询 4 工具 (复用既有 service 查询函数)
- 注册: mcp_tool_registry (19 工具既有面 +4); gate 维持默认关 (owner 显式开启才对外)
- **验收**: MCP client 可列 4 工具并查询; 未开 gate 时零暴露; 测试覆盖工具 schema

### F — 语义过滤异步化 (1 天)

**现状**: semantic_verdict 同步入口被采集 loop 线程调用 → D2 后诚实跳过 (恒 fail-open), semantic_filter gate「存在但采集路径不可用」。

- 方案 (最小面): 判别移出采集热路径 — **post-ingest 化** (采集落库后由 post-ingest 链异步补偿判别, deny → 隐藏/打标, 不阻塞采集); 复用 v1_signal_bridge/collect 的 post-ingest 模式
- 保留 D2 的 loop 检测作为兜底防线 (防回归); obs 面补 semantic 判别量/拒绝量
- **验收**: 24h 窗 semantic_filter 判别量 >0 (真调用 LLM); reject 条目可见; 采集时延无劣化
