## 0. 第一性原理（产品本质）

1. **工作台 ≠ 聚合器**：采集是管道不是产品。用户打开工作台是来**形成判断、沉淀知识、采取行动**。
2. **安全从业者 = 判断密集型**：核心增值是把碎片资讯变成"可决策的结论"（威胁定级、合规对照、技术研判）。
3. **集成 dsh ≠ 依赖 dsh**：hotspot 独立可运行；dsh 是可选推理增强层。dsh 故障 → LLM 直连兜底，任何核心功能不因 dsh 缺失而中断。
4. **wiki-first 存储**：知识域以 `llm-wiki-2.0` md 为唯一真相源，SQLite 做投影索引。
5. **双真源裁决**：知识域文件为真相（DB 仅投影）；行动域 DB 为真相（todos/reviews/kl_queue），复习结果单向投影回 wiki frontmatter。
6. **能力 = 固定模板 × 确定性落位**：AI 出稿不做自由对话，每个能力 = 固定输入材料 + 固定提示词模板 + 固定输出落位（继承 dsh-SecNews cap 铁律）。

## 2. 整合架构（技术路线）

### 2.1 架构决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 宿主 | **hotspot（FastAPI + React）为主壳** | 功能最全、已有 2,662 测试、知识域已就位 |
| AI 出稿 | **cap 模板库移植为 Python（`backend/services/cap/`）** | 固定模板 + SSE 在 FastAPI 天然可行；零 dsh 依赖 |
| 深度分析 | **dsh bridge（HTTP 桥接运行中 dsh 实例）+ LLM 直连兜底** | 复用 dsh 的 agent-loop/subagent；`DSH_ENDPOINT` 可选；不可达自动降级 |
| 知识域 | **llm-wiki-2.0 为唯一真相源，`knowledge/` 归档** | 消除双目录 |
| 管线 | **kl_queue 表落地，KL 状态机改队列驱动** | 可观测（漏斗/死信/重跑） |
| 前端 | **Workbench 5 视图取代 /data 三层，报纸风视觉延续** | 判断密集型工作台语义 |
| feature gate | **`workbench` / `dsh_integration` 两个新 gate** | 灰度切换，老视图保留至 v0.7 |

## 4. UI 设计（美观 + 判断密集型）

### 4.1 设计语言：延续报纸风，强化"判断层级"

- **视觉基调**：继承 hotspot editorial 报纸风（白纸黑字 + 报头 + 栏线）与 dsh-SecNews newspaper.css 的优点，统一为 **"晨报工作台"** 语义。
- **判断色系统**：不滥用彩色。仅三色表意：
  - 🔴 红 = 需要行动（严重 CVE、到期复习、死信）
  - 🟡 黄 = 需要注意（stale 源、超预算、未读待研判）
  - 🟢 绿 = 完成态（published、同步成功）
- **字号层级**：报头大标题（今日主线）→ 栏目标题（板块）→ 卡片标题 → 正文；代码/数据用等宽字体。

### 4.2 布局

```
┌──────────────────────────────────────────────────────┐
│ 报头: SecNews · 2026-08-24 · [dsh 状态灯] [今日采集 N] │
├────────┬─────────────────────────────────────────────┤
│ 左导航  │  当前视图内容                                │
│ Briefing│  (可滚动、J/K 键盘动线)                      │
│ Pipeline│                                             │
│ Knowledge│                                            │
│ Analyze │                                             │
│ Settings│                                             │
├────────┴─────────────────────────────────────────────┤
│ colophon: 管线健康度 raw→refine→published · token 今日 │
└──────────────────────────────────────────────────────┘
```

- **顶部状态栏**（每视图常驻）：dsh 连接灯（绿=直连 / 黄=LLM 降级 / 红=断开）、今日采集数、管线漏斗数字、token 日用量。
- **键盘动线**：扫读视图 J/K 上下、M 标已读、S 收藏、D 研判（继承 dsh-SecNews 报纸键盘 UX）。
- **空态/加载态**：骨架屏 + 每视图首次进入引导文案（"今日简报：暂无新资讯，点击刷新"）。
- **响应式**：桌面优先（1280 容器），窄屏降级为单栏 + 汉堡导航。

## 5. 后端健壮性设计

### 5.1 降级链（全链路兜底）

```
用户点击「深度研判」
  → dsh 可达? → 是 → dsh bridge (独立 subagent) → 结果落批注
              → 否 → LLM 直连 (ai_hub, heavy 档) → 结果落批注
              → LLM 也无 key/超预算 → 返回"AI 暂不可用，已保留材料"
                                    → 前端明确提示（不静默）
```

| 层 | 降级策略 |
|---|---|
| dsh | `DSH_ENDPOINT` 未配置/不可达 → 跳过 bridge，直连 LLM；health API 暴露状态 |
| LLM provider | 按 fallback_order 链式降级（ollama→qwen→openai）；429 重试 1 次后入死信 |
| 知识写入 | cap 出稿写批注失败 → 材料留会话，不阻塞主流程 |
| 管线 | 单条失败停留原阶段 + 死信可见 + 可重跑（不冒泡） |

### 5.2 SSE 出稿通道（cap 引擎，每请求流）

- **协议**（继承 dsh-SecNews，Python 化）：`open{capability,run_id}` → `chunk{delta}` → `done{artifact_path}` / `error{message}`
- **实现**：FastAPI `StreamingResponse`（每请求独立），`asyncio.Queue` 桥接 LLM 异步流；客户端断连检测 `request.is_disconnected()` → 取消生成。
- **并发**：每能力信号量（flash 共享队列、heavy 每任务独立）；超时（flash 60s / heavy 300s）自动取消。
- **安全**：模板能力**不接受自由对话**（输入即材料文本，无 prompt injection 面）；SSE 无跨域问题（同源）。

### 5.3 数据一致性

- **wiki-first 强约束**：采集/导入经 quality 后**先写 md 再写 DB**，md 失败 → 不入 SQLite + 告警。
- **单向投影**：复习（DB 真相）→ mastery/last_reviewed 投影回 frontmatter；**禁止** DB→文件反向覆盖知识内容。
- **kl_queue 可观测**：每阶段 transition 写队列行（stage/attempts/error/model_tier/tokens），30 天 published 行自动清理。

### 5.4 安全

- 新增路由全部走 feature gate（`workbench` / `dsh_integration`），关闭时 404（沿用 core/extension 白名单机制）。
- dsh bridge 仅内网（DSH_ENDPOINT 默认 localhost），无凭据透传；会话留档仅存 input/output 摘要。
- token 台账含预算阈值告警（超限自动降级为仅脚本）。

### 5.5 可观测与测试

- 每个新端点有 `job_done` 式事件留痕；关键失败打结构化日志。
- 测试新增：cap 模板单测（输入→输出契约）、SSE 流式 e2e（open→chunk→done）、dsh bridge 降级（DSH_ENDPOINT 指向不可达端口 → 自动 LLM 直连）、kl_queue 全链路（enqueue→published）、Pipeline API。
- 门禁：`pytest ≥ 基线` + `ruff 0` + `generate_meta.py --check` + `tsc/vitest/vite build`。
