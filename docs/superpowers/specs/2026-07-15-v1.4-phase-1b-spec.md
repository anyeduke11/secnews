## 3. 详细规范

### 3.1 书签导入 (Task 2.1)

**目标**: 导入 Chrome/Edge 浏览器书签 JSON，去重后写入 knowledge/items/

**书签 JSON 格式**（Chrome 导出标准）:
```json
{
  "name": "书签栏",
  "children": [
    {
      "type": "url",
      "name": "零信任架构指南",
      "url": "https://example.com/zero-trust"
    },
    {
      "type": "folder",
      "name": "安全",
      "children": [...]
    }
  ]
}
```

**API**:
```
POST /api/knowledge/bookmarks/import
Content-Type: application/json
Body: { "bookmarks": <Chrome bookmarks JSON> }

Response 200: {
  "imported": 12,
  "skipped_duplicates": 3,
  "skipped_invalid": 1,
  "dead_links": 2
}
```

**Service**: `backend/services/bookmark_sync.py`
- `parse_chrome_bookmarks(json_data: dict) -> list[dict]`: 递归遍历 children，提取 type=url 的节点，保留 folder 名作为 tag
- `import_bookmarks(items: list[dict]) -> dict`: 去重（复用 `data_cleaning.url_fingerprint` + 检查 existing items）→ 写入 .md（source="bookmark"）→ 同步 SQLite

**去重规则**:
- URL 指纹去重（与现有 knowledge_items 对比）
- 书签内部去重（同 URL 多次出现，合并 tags）

**代理验证**:
- 可选，通过 `data_cleaning.validate_url` 验证
- 无效 URL 标记 tags 含 "dead_link"，不阻断导入
- 默认不验证（`validate=False`），用户可通过 query param `validate=true` 开启

### 3.2 归档同步 (Task 2.2) — 方案调整

**背景**: Phase 1a 发现 history.py 无 archive 端点，归档逻辑在 scheduler 定时任务中。

**调整方案**: 改为"手动导入历史资讯到知识库"
- 用户在 HistoryPage 浏览归档资讯时，可选择条目导入到知识库
- 新增 API: `POST /api/knowledge/import-from-history`

**API**:
```
POST /api/knowledge/import-from-history
Body: { "item_ids": [1, 2, 3] }  # hotspot 表的 id 列表

Response 200: {
  "imported": 3,
  "skipped_duplicates": 0,
  "errors": []
}
```

**Service**: `backend/services/history_import.py`
- 从 hotspots 表读取指定 id 的条目（url、title、summary、category）
- URL 指纹去重（与现有 knowledge_items 对比）
- 写入 .md（source="secnews_archive"，正文用 summary）→ 同步 SQLite

**前端**:
- HistoryPage 每个 item 卡片新增"📚 归档到知识库"按钮
- 点击后调用 `/api/knowledge/import-from-history`
- 成功后显示 toast 提示

### 2.3 知识图谱 (Task 2.3)

**目标**: 用 ECharts 力导向图可视化概念网络

**后端 API**:
```
GET /api/knowledge/graph?domain=security

Response 200: {
  "nodes": [
    { "id": "zero-trust", "label": "零信任", "domain": "security", "count": 5, "wiki": "hotspot" },
    { "id": "xdr", "label": "XDR", "domain": "security", "count": 3, "wiki": "hotspot" }
  ],
  "edges": [
    { "source": "zero-trust", "target": "xdr", "weight": 2 }
  ]
}
```

**图构建算法**:
1. 节点：`knowledge_concepts` 表所有 concept（count = len(source_items)）
2. 边：扫描所有 `knowledge_items.concepts`，两个 concept 出现在同一 item 中则边权重 +1
3. domain 过滤：可选，只返回指定 domain 的节点
4. **本地 wiki 联邦**：Phase 1b 暂不实现，所有节点 wiki="hotspot"

**Service**: `backend/services/graph_builder.py`
- `build_graph(domain: Optional[str]) -> dict`: 扫描 concepts + items，构建 nodes/edges
- 结果缓存到 `knowledge_graph` 表（updated_at 戳），5 分钟内复用缓存

**前端**:
- 安装 `echarts` + `echarts-for-react`
- 新建 `KnowledgeGraph.tsx` 组件，替换 KnowledgePage 左栏占位
- 力导向图配置：节点大小 = log(count)+10，颜色按 domain 区分
- 交互：点击节点 → 调用 `onSelectConcept(slug)` → 高亮相关 items
- 空状态："暂无概念。请先编译知识库（POST /api/knowledge/compile）"

### 2.4 筛选器 (Task 2.4)

**目标**: 支持领域/主题/类型/难度/时间多维筛选

**后端 API 扩展**:
```
GET /api/knowledge/items?domain=security&topic=zero-trust&type=analysis&difficulty=intermediate&since=2026-07-01&until=2026-07-15&limit=50&offset=0
```

新增 query params:
- `topic`: 二级主题
- `type`: news | analysis | paper | tutorial | tool | opinion
- `difficulty`: beginner | intermediate | advanced | expert
- `since` / `until`: ISO 日期，按 ingested_at 过滤

**Repository 扩展**:
- `KnowledgeRepo.list_items()` 新增 topic/type/difficulty/since/until 参数
- `KnowledgeRepo.list_topics(domain) -> list[str]`: 返回指定 domain 下的 topic 列表（用于前端联动筛选）

**前端**:
- 新建 `KnowledgeFilters.tsx` 组件
- 4 个下拉：领域（domain）/ 主题（topic，联动）/ 类型（type）/ 难度（difficulty）
- 1 个时间选择：本周 / 本月 / 全部
- 筛选变化 → 重新 fetch items
- 放在 KnowledgePage 底部 items 列表上方

### 2.5 编译 API (Task 2.5)

**目标**: 触发知识编译流程（分类 + 打标 + 概念提取）

**后端角色**: 只创建任务 + 更新状态，**不执行 LLM 调用**（由 Agent 通过 skill 执行）

**API**:
```
POST /api/knowledge/compile
Body: { "item_ids": ["a1b2c3", "d4e5f6"] }  # 可选，不传则编译所有 compiled=false 的条目

Response 200: {
  "task_id": 42,
  "status": "pending",
  "items_to_compile": 15
}
```

**Service**: `backend/services/compiler.py`
- `create_compile_task(item_ids: Optional[list[str]]) -> dict`
  - 如果指定 item_ids，验证它们存在且 compiled=false
  - 如果不指定，查询所有 compiled=false 的条目 id
  - 创建 `knowledge_task`（task_type="compile", params={"item_ids": [...]}）
  - 在 `knowledge/learning/tasks/pending/` 写入任务文件（`task-{timestamp}.md`），供 Agent 扫描
  - 返回 task_id + 待编译条目数

**任务文件格式**（`knowledge/learning/tasks/pending/task-{timestamp}.md`）:
```yaml
---
task_type: "compile"
status: "pending"
created_at: "2026-07-15T10:00:00Z"
params:
  item_ids: ["a1b2c3", "d4e5f6"]
---

# 编译任务

请对以下知识条目执行编译：
- [[a1b2c3]]
- [[d4e5f6]]

## 编译步骤
1. 分类 + 打标（domain/topic/type/difficulty + tags）
2. 概念提取（写入 concepts/{slug}.md）
3. 概念关联（更新 graph.json）
4. 标记 compiled=true
```

**Agent 协作**:
- Agent 扫描 `pending/` 目录 → 读取任务 → 调用 knowledge-base-manager skill → 编译 → 移动到 `done/` → 后端 watchdog 同步 .md 变化到 SQLite
- 后端不等待 Agent 完成，API 立即返回 task_id

### 2.6 健康度审计升级 (Task 2.6)

**目标**: 真实计算 orphan_items / stale_concepts / gap_analysis

**API 升级**:
```
GET /api/knowledge/health

Response 200: {
  "total_items": 50,
  "total_concepts": 12,
  "compiled_count": 30,
  "compiled_ratio": 0.6,
  "orphan_items": 5,
  "stale_concepts": 2,
  "gap_analysis": [
    { "domain": "security", "coverage": 0.8, "suggestion": "覆盖良好" },
    { "domain": "ai", "coverage": 0.3, "suggestion": "建议补充 AI 安全相关条目" }
  ]
}
```

**计算逻辑**:
- `orphan_items`: `SELECT COUNT(*) FROM knowledge_items WHERE concepts = '[]'`（无概念关联）
- `stale_concepts`: `SELECT COUNT(*) FROM knowledge_concepts WHERE updated_at < datetime('now', '-30 days')`
- `gap_analysis`: 按 domain 分组，coverage = compiled_count / total_count，低于 0.5 给出建议

**前端**:
- 新建 `HealthDashboard.tsx` 组件
- 放在 KnowledgePage 左栏下方（知识图谱之下）
- 展示：总条目、已编译、孤立条目、过期概念、领域覆盖度

## 6. 关键设计决策

### 6.1 归档同步：手动导入 vs 自动 webhook
**选择**: 手动导入（POST /api/knowledge/import-from-history）
**理由**:
- Phase 1a 确认 history.py 无 archive 端点，归档在 scheduler 定时任务
- 自动 webhook 会耦合 scheduler 和 knowledge 模块
- 手动导入让用户有控制权（不是所有历史资讯都值得进知识库）
- 符合"后端不嵌入 Agent"原则

### 6.2 编译 API：后端不调 LLM
**选择**: 后端只创建任务文件，Agent 执行 LLM 调用
**理由**:
- design 文档明确"后端做数据同步/存储/API，Agent 做 LLM 调用/编译/学习"
- 后端调 LLM 会引入同步等待、超时、密钥管理复杂性
- Agent 通过 skill（knowledge-base-manager）执行编译更灵活

### 6.3 知识图谱：不实现本地 wiki 联邦
**选择**: Phase 1b 只读 hotspot wiki
**理由**:
- 本地 wiki 路径配置（local_wiki_path）默认为空
- 联邦读取需要跨目录扫描，增加复杂度
- 留到 Phase 1c 与学习路径一起实现

### 6.4 ECharts 依赖
**选择**: 安装 echarts + echarts-for-react
**理由**:
- 设计文档明确指定 ECharts 力导向图
- 项目现有前端无图谱可视化库
- echarts-for-react 是 React 封装，与现有技术栈一致
