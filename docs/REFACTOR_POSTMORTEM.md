## 二、真实问题清单 (按严重度, 均来自本次实际发现)

### 数据/安全级
1. **跨设备同步解密必然失败**: `decrypt_bundle` 用本地 salt 而非 envelope salt (两台设备 salt 不同 → 密钥不同)
2. **secrets 锁定态 push 静默丢失**: 密文置 None 被对端跳过
3. **删除永不跨端生效**: apply_bundle 无删除通道
4. **CI 从未运行**: `.gitignore` 的 `.*/` 通配把 `.github/` 也忽略了
5. **simhash 去重跨运行不稳定**: `_hash_token` 用 Python 内置 `hash()` (PYTHONHASHSEED 随机化) — 生产去重在重启后漂移, 测试 flaky 的深层根因
6. **主密钥 8 字符**: PBKDF2 600k 迭代下可离线爆破

### 正确性级
7. **MCP stdio 入口损坏**: fastapi-mcp 0.4.0 无 `run(transport=...)` — README 宣传的 Agent 集成实际不可用
8. **4 个潜在 NameError**: 未导入的 `Path/datetime/Optional/HotspotItem` (ruff F821 揪出)
9. **发布者映射被覆盖**: `publisher_registry` dict 重复 key (freebuf/安全客 被搜狗别名覆盖)
10. **迁移编号断裂风险**: 056 缺失、v2.0→v1.7 改名删除 (提交必须同批)

### 架构/工程级
11. **90% 知识条目未分类**: auto_classifier 存在但无调度 (3732/4143 domain=null)
12. **1980 个 compile 任务积压**: 无消费者 + compiled 判定死循环
13. **CodeGarden/注意力体系空转**: cg_services 1300 条系统噪音、attention_events 0 行
14. **测试污染真实知识库**: 每次全量跑改 17+ 个 items
15. **后端零 lint/零锁文件**: 10 万行无静态检查、依赖全 `>=`

## 三、可沉淀的经验 (方法论, 已在本仓库验证有效)

### 1. 重构前先冻结基线
309 个脏文件 (v0.3.0) 先分批提交再动手 — 重构的每个阶段都可回退, 避免"改了半年没提交"的灾难。**版本发布与代码提交必须同步**。

### 2. 自动化修复必须测试护航
ruff --fix 一次性改 355 文件 → 全量回归抓住 **72 个失败** (re-export 删除 + SIM118 误改)。教训: **任何批量修改后, 全量回归是唯一安全网**; 单测通过不代表全量通过。

### 3. 工具规则对特定类型不安全 → 立即禁用并记录
- `SIM118` 对 `sqlite3.Row` 不安全: `row.get()` 不存在、`"x" in row` 检查值而非键 — 两种静默错误模式
- `RUF001-3` 对中文注释误报 (全角字符)
- 处置: ruff.toml ignore + 代码注释说明**为什么**禁

### 4. re-export 契约模块要显式保护
`backend/collectors/base.py` 注释声明"符号保留供测试 monkeypatch" — F401 自动修复仍删了 `fetch_html/crawl4ai_available`。处置: `per-file-ignores` + 测试覆盖。

### 5. flaky 测试要挖根因, 不要 fixture 掩盖
`test_duplicate_similar_title` 全量 flaky → 根因是 PYTHONHASHSEED (生产级 bug), 修复比隔离测试更有价值。**测试暴露的随机性往往是生产 bug 的信号**。

### 6. 测试隔离是底线 (autouse fixture)
把 11 个模块的 knowledge 路径常量重定向 tmp_path — 根治测试污染。**测试永远不能写真实数据目录**。

### 7. 数据操作三原则: 评估 → 备份 → 执行 → 验证
- 存量任务清理: 先只读统计 → 完整 DB 快照 + CSV + 文件备份 → 执行 → 验证 DB/文件一致
- VACUUM: 生成压缩副本 → 完整性检查 → 停机替换 → 重启验证
- **任何生产写操作前先问: 备份在哪? 怎么回滚?**

### 8. Strangler 迁移模式 (crawler-v2 实证)
新体系旁路建表 (055) → 源注册脚本积累数据 (132 条) → 切流 (表驱动 + 回退常量) → 等价性测试护航。**替换旧系统时, 先并行积累数据, 再逐步切流, 保留回退**。

### 9. 测试/工具配置要与生产一致
- fixture 的 `db_path` 用 str 而生产用 Path → 隐性 bug
- fixture 的 `isolation_level` 默认隐式事务而生产 autocommit → 嵌套 BEGIN 报错
- **fixture 是生产配置的镜像, 不一致就是 bug 温床**

### 10. 修复链: 一次全量回归跑 13 分钟, 但省下的是数天的排障
每次改动后全量回归 (2426 用例) 是本仓库的"安全网"。CI 必跑、本地必跑。

## 四、禁区 (红线, 违反必出事故)

| # | 禁区 | 本次教训 |
|---|---|---|
| 1 | **不在无备份的生产库上做写操作** | 任务清理/日志清理前必备份 |
| 2 | **不在运行中的服务上替换 DB 文件** | VACUUM 替换需停机, 否则丢 WAL 数据 |
| 3 | **不信任自动修复工具对领域类型的假设** | SIM118 × sqlite3.Row 两种静默错误 |
| 4 | **不删除 re-export 符号** | base.py 契约破坏 → 72 测试失败 |
| 5 | **不用内置 `hash()` 做持久化指纹** | PYTHONHASHSEED 跨进程随机 |
| 6 | **测试不写真实数据目录** | knowledge/ 污染需手动恢复 |
| 7 | **不并行修改同一文件** | 子代理/会话冲突 (App.tsx 并发改动) |
| 8 | **不发布"宣布了但没实现"的功能** | CodeGarden 联动/注意力体系空转的教训 |
| 9 | **不用 `.*/` 通配 gitignore 隐藏目录** | `.github/` 被误伤 → CI 从未运行 |
| 10 | **不绕过迁移编号/改名** | 056 缺失、v2.0→v1.7 改名必须同批提交 |
| 11 | **不在锁定的 vault 状态下同步 secrets** | 密文置 None 静默丢数据 |
| 12 | **不写死时间戳到测试断言** | cached_at 写死 2026-08-01 → 随真实时间过期 |

## 五、企业化改进建议 (让开发更成熟)

### 流程层
1. **变更管理**: 版本发布 = 代码提交 + CHANGELOG + 测试全绿 三同步; 禁止"发布宣布了代码没提交"
2. **代码评审**: 单人项目也要有"第二双眼睛" — 用 AI 子代理交叉验证 (本次 4 路审计 + 我交叉核实的模式可复用)
3. **技术债台账**: 维护债务清单 (如 docs/ARCHITECTURE.md 第八章), 每轮迭代偿还一部分, 而非无限累积

### 工程层
4. **CI 是硬门槛**: lint (ruff) + 测试 + 构建 + 依赖审计 (pip-audit/npm audit) 全绿才能合入
5. **依赖供应链**: 锁文件 + 可选依赖分离 (crawl4ai 不再拖 723MB) + 版本升级走评审
6. **可观测性**: 错误必带 trace_id + 结构化日志; 关键路径 (同步/采集/调度) 有告警通道
7. **数据资产**: 每日备份 + 保留策略 + 恢复演练; 敏感数据 (secrets) 强口令 + 加密存储

### 治理层
8. **spec-first 但以代码为准**: 文档 (ARCHITECTURE.md) 数字全部从代码核对, 防漂移
9. **测试隔离制度化**: conftest autouse fixture 保证任何测试都不碰真实环境
10. **渐进重构**: 大改造用 strangler (旁路→切流→退役), 每步可回退可验证

### 下一步建议 (按优先级)
- P0: 恢复演练 (备份能否真正还原)、同步删除通道的端到端验证
- P1: crawler-v2 Phase 2 (源注册表驱动调度器/健康状态机)、CodeGarden 联动真执行器
- P2: 前端 React Query 评估 (若跨页状态膨胀)、知识分类缺口 (61.4% 确定性分类上限)
