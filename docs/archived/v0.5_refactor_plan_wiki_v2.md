> **版本**: 0.5 v2 ｜ **日期**: 2026-08-21 ｜ **状态**: 待执行

## §0 业务愿景

**v0.5 终态用户场景**：Duke 每天打开 hotspot 看到的是"今天发生了什么"（Today view，1 屏，在 `DataLayerPage` 顶部 summary card 实现，不新建 `TodayPage`），而不是 v0.4 的多 tab 多视图切换。30 天前的资讯自动沉淀到 `llm-wiki-2.0/` 本地 markdown 仓库，可读、可查、可改（git diff 友好），SQLite 退化为 search/index 缓存。AI 评分带 confidence，被新证据覆盖的旧条目自动 supersession，长期不访问的旧事实 retention 健康度按 Ebbinghaus 曲线（`current = 0.9 ^ (days/7)`）逐步降低（60 天 ≈ 0.41 接近 stale 边缘，< 0.3 标 stale）。

**v0.4 现状对照（避免误诊）**：v0.4 已经是 file-first 架构（`backend/services/knowledge_sync.py:5-7` 写"md 是唯一真相源，SQLite 是可随时从 md 全量重建的只读索引"；CLAUDE.md 的 `Knowledge system` 段也写"file-first, SQLite is read cache"）。v0.5 不是要把 SQLite 退化为缓存（已经是了），而是**在 v0.4 file-first 基础上加 4 块增量**：

1. **新 frontmatter 字段**：confidence / supersedes / superseded_by / retention
2. **6 种 typed relationships**（v0.4 graph.json 只有 `related`）
3. **30 天归档自动化**（v0.4 4152 个 items 都在 `knowledge/`，没自动迁到 `llm-wiki-2.0/`）
4. **Ebbinghaus 衰减 + 校准回路**（v0.4 无）

**v0.5 不做什么**：不做工作看板三栏 UI（保留 API 给日报复用）、不做 AiHub 跨 3 里程碑 strangler（直接 1 PR）、不做 ⌘K 全局检索（FTS5 已覆盖 80%）、不做多 agent 协作规范（单人项目用不上）、不做 t_advice 闭环（hypothetical user 场景）。

## §4 数据流（v2 视角，llm-wiki-2.0 驱动）

```
抓取层：
爬虫抓取 → raw_items 表 (热, 30 天) → quality gates → hotspots/items 表
                                                            ↓
                                                          [M2 触发]
                                                            ↓
归档层（v2 新增）：
30 天后非收藏条目 → wiki_archiver.py → llm-wiki-2.0/items/{hash}.md
                                     → llm-wiki-2.0/sources/{hash}.md (抓取元数据)
                                     → llm-wiki-2.0/concepts/{slug}.md
                                     → llm-wiki-2.0/retention.json (Ebbinghaus)
                                     → llm-wiki-2.0/graph.json (6 种边)

索引层：
SQLite 索引（heatmap/搜索用，90 天滑动窗口） ← knowledge_sync.py 双向同步
                                          ↑
                              llm-wiki-2.0/ 是 source of truth
                              SQLite 是 search/index 缓存

AI 层（M3 起）：
ai_hub.py 合并 → t_confidence / t_supersede / t_digest
                ↓
            写回 llm-wiki-2.0/（digest/*.md / items/*.md frontmatter 增 confidence / supersedes 字段）

结晶层（M4 起）：
t_digest → llm-wiki-2.0/digest/{date}-{slug}.md
       → 关联 items + concepts 链接
       → user "今日结晶"操作触发
```

**与 v0.4 现状的关键差异**：
- markdown 文件夹从 `knowledge/` 扩到 `llm-wiki-2.0/`
- confidence 字段（v0.4 无）
- supersession 链（v0.4 无，靠 lifecycle 线性推进）
- Ebbinghaus 衰减（v0.4 无，按时间硬截断）
- typed relationships 6 种（v0.4 只有 2 种）
- SQLite 退化为缓存（v0.4 SQLite 是 source of truth）

**v0.4 兼容性**：
- v0.5 期间 v0.4 数据双轨：v0.4 之前数据留在 `knowledge/`，v0.5 之后新数据进 `llm-wiki-2.0/`
- `knowledge/_SCHEMA.md` 标 deprecated 但兼容
- M5 一次性迁移脚本把**实测 4152 个 items + 98 个 concepts**（`knowledge/_MAP.md:15-16`）迁到 `llm-wiki-2.0/`

## §10 SPEC 规范条款（v1 §7 + v2 新增）

1. **配置分层（v2 简化）**：llm_task_settings（动态，即时）> llm.yaml（静态，重启）> ~~代码默认~~。新 AI 参数进前两层。
2. **降级语义**：AI 能力失败永远有确定性兜底（§6 t_confidence / §8 t_digest 表），禁止抛 500；前端失败态显「—」。
3. **迁移规范**：迁移文件只允许轻量 DDL（单表 <1s）；数据回填/清洗一律离线脚本；幂等。
4. **DB 写入规范**：批量写单事务；新表必须同时提交 retention 台账条目。
5. **双开关**：feature_gates（Pydantic Settings 字段 + `HOTSPOT_*` env 变量，路由存废）与 llm.yaml（能力降级）正交。**不是** TOML 文件配置。
6. **同步契约**：新表必须在 `sync_bundle.py` 显式声明「同步/设备本地」二选一，默认设备本地。
7. **版本规范**：`backend/version.py` 与 `frontend/package.json` 同步；发布前跑 `generate_meta.py`。
8. **富规格原则**：测试套件即规格，**2286 + 286** 用例是行为契约（CLAUDE.md 实测 2286+；v1 写 2288 是估时，v2 统一为 2286 + 2 误差容许，与 §1 全程法一致）。
9. **归档契约**（v2 新增）：所有非收藏 hotspots/items 30 天后必须落 `llm-wiki-2.0/`，SQLite 仅保留 search/index 缓存（90 天滑动窗口）。
10. **schema 唯一**（v2 新增）：`llm-wiki-2.0/schema/SCHEMA.md` 是 frontmatter 字段定义唯一真相源，hotspot `knowledge/_SCHEMA.md` 标记 deprecated 兼容旧 items。
11. **source of truth**（v2 新增）：markdown 文件（`llm-wiki-2.0/`）是 source of truth，SQLite 是衍生缓存。**任何数据修改走 markdown，SQLite sync 跟随**。
12. **typed relationships**（v2 新增）：6 种边类型（uses/depends/contradicts/caused/fixed/supersedes），关系带 weight + source_observation_count。
