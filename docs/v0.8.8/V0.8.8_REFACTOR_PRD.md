| A. 确证孤儿 | 无前端调用 + 无后端 import + 无 job 调度 + 无 MCP tool 消费 + 无测试依赖（除自身测试） | 允许物理删除 |
| B. 疑似孤儿 | 满足 A 但存在动态路径拼接 / 反射调用风险 | 先加 `410 Gone` + 观测 1 个版本，再删 |
| C. 重复能力 | 两个端点提供等价能力，其中一个是历史遗留 | 保留被消费方，另一个走 B 流程 |

> **「文本命中 ≠ 真实调用」**：前缀子串匹配只能作为候选生成器，不可作为裁决依据。每条候选必须落到**具体调用点文件+行号**。

#### 3.3.2 「消融实验」的口径

本产品为单用户本地工具，**无法做统计学 A/B**（无用户分流、无统计功效）。因此本 PRD 的「消融」定义为**反事实消融（counterfactual ablation）**：

- 手段：将目标能力对应的 Feature Gate 置为 `false`（或临时注释注册行），跑全量回归。
- 观测：失败用例差集、路由数变化、启动耗时、链路 p95、DAG 入度。
- 结论形式：**「关闭 X 后，Y 会红 / Z 无变化」**，而非「X 提升转化 N%」。

#### 3.3.3 「可量化」的口径

所有指标必须先测基线（Phase 0），再给相对目标。**基线未测得前，绝对数值目标一律视为无效**，不得写入验收。

#### 6.3.1 R-17 数据生命周期兼容性（新增）

> R-17 取消备份作业，故 §6.3 第 2 条的「发布前 `backup-verify` 通过」前置条件**对 R-17 不适用**——该端点随备份链一并退役。R-17 以**重建能力验收**替代**备份校验验收**。

| 项 | 规则 |
|---|---|
| 表结构 | **不动**（X-6）。R-17 只删行、停作业，不新增 / 不删除 / 不改列 |
| 行删除边界 | 仅三类：① `hotspots` 中 `ingested_at < now-30d` 且**未被收藏**的行；② 日志类环形截断的最旧行；③ 随 `hotspots` 级联 / 显式同步删除的 `hotspot_tags` / `ai_scores` 行 |
| 行删除顺序 | **先写 md → 回读校验 → 通过才删 DB 行**。校验失败即中止本批并计数（fail-loud），**绝不先删后补** |
| md 写入方向 | 只**新增** `llm-wiki-2.0/feed/` 目录；**不修改、不删除**任何既有 md（§6.3 wiki-first 约束） |
| 恢复路径 | 删库 → `scripts/rebuild_hot_index.py --from-cold` → 从 md 重建 `hotspots` + FTS + `hotspot_tags`。**该能力必须先于首次删行交付**（p2.5.1 修订：沉降拆 **P2.5-3a 只写**（不删行，先产出真实 `feed/*.md`）与 **P2.5-3b 删行**；P2.5-4 重建以 3a 的冷层为输入通过 T4 后，3b 才允许开启） |
| 幂等性 | 沉降按 id 幂等（目标 md 已含该 id → 跳过）；重建按 id upsert 幂等 |
| 数据丢失边界 | 已下沉并删行的数据**仅存于 `llm-wiki-2.0/feed/`**（本地单副本，X-10 已声明该风险由 owner 接受）。回滚代码 revert 后**不会自动恢复 DB 行**，须跑重建管道 |
| 兼容性门禁 | 实施后须实测：`favorites.hotspot_id` **可解析率不下降**（基线 8/9，见 §4.17 验收标准⑤）；`/api/v1/signals` `/api/v1/cases` `/api/hotspots` `/api/favorites` 四端点 200 且返回行数不变 |

|---|---|
| 核心闭环 | 「资讯获取 → 知识沉淀 → 落地执行」，对应四菜单 `资讯 → 知识 → 行动` |

| 可重建（非可拷贝） | R-17 的备份语义：不再拷贝 DB 文件，改为保证「DB 丢失后能从 md 重建热索引」 |
